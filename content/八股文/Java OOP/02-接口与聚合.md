# 接口与聚合

### 接口（interface）的规则

**概念**：接口是一份行为合同（a contract of behaviors），规定实现类必须做什么，而不规定怎么做

**一句话**：接口用 interface 定义、类用 implements 实现，一个类可以实现多个接口；接口方法默认 public abstract，字段默认 public static final；实现类必须实现所有抽象方法，否则自己要声明为 abstract；JDK 8 起接口还可以有 default 和 static 方法。

**详细解释**：
语法：`public interface Shape {}`、`public class Triangle implements Shape {}`。
接口像类一样可以有方法和变量，但方法默认是 abstract 的，只有签名没有方法体；它是类的 blueprint：Specifies what a class must do but not how to do it。
Java 的类不能多继承，但接口可以：一个类可以 implements 多个接口，一个接口可以 extends 多个接口。
类实现接口却没有给出全部方法的实现时，这个类必须声明为 abstract。
接口里的方法默认 public，所以实现类里的方法也必须写成 public（不能缩小访问权限）。
接口字段默认 public static final，是常量，不能被重新赋值；接口没有构造器，不能被实例化。

**问题**：接口有什么特点？类实现接口时要注意什么？

**答案要点**：
1. 接口是行为合同，规定"做什么"不规定"怎么做"
2. 方法默认 public abstract，字段默认 public static final
3. 一个类可以实现多个接口，接口可以 extends 多个接口
4. 实现类要实现全部抽象方法，否则必须声明为 abstract
5. 实现方法必须是 public；JDK 8 起接口可以有 default / static 方法

**常见陷阱**：
- ❌ 实现接口方法时省略 public
- ✅ 接口方法默认 public，实现时不加 public 就是缩小访问权限，编译错误
- ❌ 在实现类里修改接口里定义的变量
- ✅ 接口变量都是 public static final 常量，不能重新赋值

**追问**：
- Q: 接口里能写有方法体的方法吗？
- A: JDK 8 起可以写 default 方法和 static 方法，JDK 9 起还可以写 private 方法；普通抽象方法没有方法体

**代码题**：下面代码能编译吗？

```java
interface Config {
    int MAX = 10;
}
Config.MAX = 20;
System.out.println(Config.MAX);
```

- [ ] 20
- [ ] 10
- [x] 编译错误
- [ ] 抛出 UnsupportedOperationException

解析：接口里的变量默认是 public static final 常量，给 Config.MAX 重新赋值会编译报错。

**代码题**：下面代码能编译吗？

```java
interface Shape {
    double area();
}
class Square implements Shape {
    double area() { return 4; }
}
System.out.println(new Square().area());
```

- [ ] 4.0
- [ ] 4
- [x] 编译错误
- [ ] 0.0

解析：接口方法默认是 public，Square 实现时没写 public，相当于把访问权限缩小成了默认访问，编译报错；要写成 public double area()。

**判断题**：
- ✅ 一个类没有实现接口的全部抽象方法时，必须声明为 abstract —— 否则编译错误
- ❌ 接口可以有构造器 —— 接口不能被实例化，也没有构造器

### 聚合与组合（HAS-A）

**概念**：一个类持有另一个类的引用作为字段，就是聚合（Aggregation）或组合（Composition），表达 HAS-A 关系

**一句话**：继承表达 IS-A（Dog is an Animal），聚合 / 组合表达 HAS-A（Employee has an Address）；没有 IS-A 关系时，用聚合同样能复用代码，避免把同样的字段在多个类里重复写，修改时也不会不一致。

**详细解释**：
```java
class Address {
    String city;
    String zipcode;
}
class Employee {
    String id;
    String name;
    String email;
    Address address;   // Employee HAS-A Address
}
```
如果没有 Address 这个对象：要把 city、zipcode 直接写进 Employee；以后 Company 也有地址，又得再写一遍；字段改名（zipcode → postalCode）时要到处改，容易不一致。
聚合提供灵活性和独立性：Address 对象可以独立于 Employee 或 Company 存在。
聚合和组合的区别：聚合是弱 HAS-A，部分可以独立存在（员工和地址）；组合是强 HAS-A（part-of），部分随整体一起创建和销毁（房子和房间）。

**问题**：什么是聚合（HAS-A）？为什么要用聚合？

**答案要点**：
1. 一个类持有另一个类的引用作为字段，就是 HAS-A
2. 继承是 IS-A，聚合 / 组合是 HAS-A
3. 没有 IS-A 关系时，聚合同样能复用代码
4. 避免重复字段，修改集中在一处，不会不一致
5. 聚合的部分可独立存在，组合的部分随整体创建和销毁

**对比**：
| | 聚合 Aggregation | 组合 Composition |
|---|---|---|
| 关系强弱 | 弱 HAS-A | 强 HAS-A（part-of） |
| 生命周期 | 部分可以独立存在 | 部分随整体创建和销毁 |
| 例子 | 员工和地址 | 房子和房间 |

**常见陷阱**：
- ❌ 为了复用代码，让 Employee extends Address
- ✅ Employee 不是一种 Address，应该让 Employee 持有一个 Address 字段

**追问**：
- Q: 多个对象聚合同一个 Address 对象，会有什么影响？
- A: 它们共享同一个引用，通过任意一个修改 Address，其他对象看到的也会变；需要独立时要各自复制一份

**代码题**：下面代码输出什么？

```java
class Address {
    String city;
    Address(String city) { this.city = city; }
}
class Employee {
    Address address;
    Employee(Address address) { this.address = address; }
}
Address home = new Address("Boston");
Employee a = new Employee(home);
Employee b = new Employee(home);
a.address.city = "NYC";
System.out.println(b.address.city);
```

- [x] NYC
- [ ] Boston
- [ ] null
- [ ] 编译错误

解析：a 和 b 聚合的是同一个 Address 对象（只复制了引用），通过 a 修改 city，b 看到的也是 NYC。

**判断题**：
- ✅ 聚合可以在没有 IS-A 关系的类之间复用代码 —— 通过持有对方的引用来复用
- ❌ 组合关系中，部分可以脱离整体独立存在 —— 那是聚合；组合的部分随整体一起创建和销毁

### 继承 vs 聚合

**概念**：继承（IS-A）和聚合 / 组合（HAS-A）都能复用代码；只有 IS-A 关系在对象整个生命周期都成立时才用继承，否则用聚合

**一句话**：继承把子类和父类紧紧绑在一起，父类一改子类就得跟着改；聚合只依赖对方的公开方法，更灵活，方便替换和做 mock 测试，还能用来绕开菱形问题——这就是"组合优于继承"。

**详细解释**：
原则：Inheritance should be used only if the IS-A relationship is maintained throughout the lifetime of the objects involved; otherwise, use aggregation.
灵活性：父类某个方法的返回类型变了——用继承时子类没有选择，只能改自己的实现；用聚合时只要改一下接收返回值的变量类型。
测试：聚合的依赖可以替换成 mock 对象，方便单元测试。
解决菱形问题：不让 D 同时继承 B 和 C，而是把 B 和 C 作为 D 的成员变量，通过 b.doSomething() 或 c.doSomething() 明确调用，消除歧义。

**问题**：继承和聚合怎么选？为什么说组合优于继承？

**答案要点**：
1. IS-A 关系在整个生命周期都成立才用继承
2. 继承耦合紧，父类变化会直接影响子类
3. 聚合只依赖公开接口，更灵活、更容易替换
4. 聚合方便用 mock 做单元测试
5. 聚合可以绕开多继承的菱形问题

**对比**：
| | 继承 Inheritance | 聚合 Aggregation |
|---|---|---|
| 关系 | IS-A | HAS-A |
| 耦合 | 紧，父类变化影响子类 | 松，只依赖公开方法 |
| 运行时替换 | 不能 | 能换成别的实现或 mock |
| 数量 | 只能继承一个类 | 可以持有多个对象 |

**常见陷阱**：
- ❌ 只要能复用代码就用继承
- ✅ 先判断 IS-A 是否始终成立，不成立就用聚合

**追问**：
- Q: 举一个用继承会出问题、用组合更好的例子？
- A: Stack extends Vector：栈继承了 Vector 的 add(index)、get(index) 等方法，可以绕过后进先出的规则；如果 Stack 内部持有一个 List，只暴露 push / pop，就不会有这个问题

**代码题**：下面代码输出什么？

```java
class B { String doSomething() { return "B"; } }
class C { String doSomething() { return "C"; } }
class D {
    private B b = new B();
    private C c = new C();
    String run() { return b.doSomething() + c.doSomething(); }
}
System.out.println(new D().run());
```

- [x] BC
- [ ] B
- [ ] C
- [ ] 编译错误

解析：D 没有继承 B 和 C，而是把它们作为成员变量（聚合），通过 b.doSomething()、c.doSomething() 明确调用，不存在菱形问题的歧义。

**判断题**：
- ✅ 用聚合可以避免多继承带来的菱形问题 —— 通过成员变量明确调用某一个对象的方法
- ❌ 只要两个类有重复代码，就应该让其中一个继承另一个 —— 继承要求 IS-A 关系始终成立，否则应该用聚合
