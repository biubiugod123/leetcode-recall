# 不可变类

### 不可变类的特点与好处

**概念**：不可变类（Immutable class）的对象在构造完成后，内部状态就不能再被改变

**一句话**：String 和 Integer、Long、Double 等包装类都是不可变类；不可变对象天然线程安全、不需要同步，可以放心地作为 HashMap / HashSet 的 key，不会产生意外的副作用，更容易推理、测试和调试，也适合函数式编程；常用于配置对象、多线程环境和 key。

**详细解释**：
定义：An object whose internal state cannot be changed after construction.
例子：String，包装类（Integer、Long、Double ...）。
Benefits：
1. 线程安全，不需要同步
2. 可以安全地作为 HashMap / HashSet 的 key（hashCode 不会变）
3. 防止意外的副作用（side effects）
4. 更容易推理、测试和调试
5. 天然支持函数式编程风格
When to use：配置对象（Configuration objects）、多线程环境、作为 key。
对不可变对象的"修改"（比如 Integer 的 a++、String 的拼接）其实都是创建了一个新对象。

**问题**：什么是不可变类？有什么好处？什么时候用？

**答案要点**：
1. 对象构造完成后状态不能再改变
2. 例子：String、Integer、Long、Double 等包装类
3. 线程安全，不需要同步
4. 适合做 HashMap / HashSet 的 key，不会有意外的副作用
5. 适用场景：配置对象、多线程环境、作为 key

**常见陷阱**：
- ❌ 认为 `Integer a = 10; a++;` 修改了原来的 Integer 对象
- ✅ a++ 是拆箱、加一、再装箱成一个新对象，原对象没变

**追问**：
- Q: 不可变对象有什么缺点？
- A: 每次"修改"都要创建新对象，频繁修改时会产生大量临时对象，比如循环拼接字符串应改用 StringBuilder

**代码题**：下面代码输出什么？

```java
Integer a = 10;
Integer b = a;
a++;
System.out.println(a + " " + b);
```

- [x] 11 10
- [ ] 11 11
- [ ] 10 10
- [ ] 编译错误

解析：Integer 是不可变的，a++ 会拆箱、加一、再装箱成新的 Integer 让 a 指向它；b 仍指向原来的 10。

**判断题**：
- ✅ 不可变对象在多线程之间共享时不需要加锁 —— 状态不会改变，不存在并发修改
- ❌ StringBuilder 是不可变类 —— StringBuilder 是可变的，String 才是不可变的

### 如何设计不可变类

**概念**：设计不可变类要阻止子类重写、把字段设为 private final、只在构造器里初始化、不提供修改方法，并对可变的引用字段做深拷贝

**一句话**：类声明为 final（或构造器 private + 工厂方法），所有字段 private final，在构造器里初始化，不提供 setter；如果字段引用的是可变对象（比如 List、数组、Date），构造时要复制一份再保存，getter 也要返回副本，否则外部仍能改掉内部状态。

**详细解释**：
How to create an Immutable class：
1. 不允许子类重写：类声明为 final；或者构造器设为 private，用工厂方法创建实例
2. 所有字段 private 且 final
3. 通过构造器初始化所有字段（可变对象要深拷贝）
4. 不提供 setter，也不提供任何能修改属性的方法
5. 字段引用其他对象时：深拷贝一份并在副本上操作，需要返回时返回副本
```java
public final class Student {
    private final String name;
    private final List<String> courses;

    public Student(String name, List<String> courses) {
        this.name = name;
        this.courses = new ArrayList<>(courses);   // 进来复制一次
    }

    public List<String> getCourses() {
        return new ArrayList<>(courses);           // 出去再复制一次
    }
}
```
只把字段写成 final 不够：final 只保证引用不能指向别的对象，List 的内容仍然可以被修改。

**问题**：怎么设计一个不可变类？

**答案要点**：
1. 类声明为 final，或构造器 private + 工厂方法，防止子类破坏
2. 所有字段 private final
3. 在构造器里初始化全部字段，不提供 setter
4. 可变的引用字段：构造时深拷贝
5. getter 返回可变字段的副本（或不可修改的视图）

**常见陷阱**：
- ❌ 认为字段都加了 final，类就不可变了
- ✅ final 只锁住引用；可变字段还要做防御性复制
- ❌ 构造器直接保存外部传进来的 List
- ✅ 外部仍持有同一个 List，修改它就改掉了"不可变"对象的状态

**追问**：
- Q: 为什么不可变类要声明为 final？
- A: 否则子类可以重写方法、添加可变状态，把子类对象当父类用时就破坏了不可变性

**代码题**：下面代码输出什么？

```java
final class Team {
    private final List<String> members;
    Team(List<String> members) { this.members = members; }
    List<String> getMembers() { return members; }
}
List<String> list = new ArrayList<>(List.of("A"));
Team t = new Team(list);
list.add("B");
t.getMembers().add("C");
System.out.println(t.getMembers());
```

- [x] [A, B, C]
- [ ] [A]
- [ ] [A, B]
- [ ] 编译错误

解析：构造器直接保存了外部的 list，getter 又把内部的 list 原样返回，外部两次修改都改到了同一个 List；final 字段并不能阻止这一点。

**代码题**：下面代码输出什么？

```java
final class Team {
    private final List<String> members;
    Team(List<String> members) { this.members = new ArrayList<>(members); }
    List<String> getMembers() { return new ArrayList<>(members); }
}
List<String> list = new ArrayList<>(List.of("A"));
Team t = new Team(list);
list.add("B");
t.getMembers().add("C");
System.out.println(t.getMembers());
```

- [x] [A]
- [ ] [A, B, C]
- [ ] [A, C]
- [ ] [A, B]

解析：构造时复制了一份，外部再改 list 不影响内部；getter 返回的也是副本，往副本里 add 不影响内部，所以始终是 [A]。

**代码题**：下面代码能编译吗？

```java
final class Money { }
class FakeMoney extends Money { }
System.out.println("ok");
```

- [ ] ok
- [x] 编译错误
- [ ] 抛出 IllegalStateException
- [ ] 什么也不输出

解析：final 类不能被继承，这正是不可变类声明为 final 的原因：防止子类重写方法、破坏不可变性。

**判断题**：
- ✅ 不可变类可以用 private 构造器 + 静态工厂方法代替 final 类 —— 子类无法调用 private 构造器，也就无法继承
- ❌ 只要所有字段都是 final，这个类就一定是不可变的 —— final 字段引用的可变对象（如 List）内容仍可被修改
