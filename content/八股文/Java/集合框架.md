# 集合框架

### HashMap 底层实现

**概念**：基于哈希表的 Map 实现，提供 O(1) 的存取性能

**详细解释**：
HashMap 在 JDK 1.8 中使用数组 + 链表 + 红黑树的结构。
数组存储 Node 节点，当发生哈希冲突时，使用链表或红黑树解决。
当链表长度超过 8 且数组长度超过 64 时，链表转换为红黑树。

**问题**：说一下 HashMap 的底层实现原理

**答案要点**：
1. 结构：数组 + 链表 + 红黑树（JDK 1.8+）
2. 扰动函数：hash = (h = key.hashCode()) ^ (h >>> 16)
3. 定位：index = (n - 1) & hash
4. 扩容：默认负载因子 0.75，扩容为原来的 2 倍

**对比**：
- vs Hashtable：HashMap 非线程安全，允许 null 键值

**常见陷阱**：
- ❌ 说成数组 + 链表就结束了
- ✅ 要提到红黑树优化，以及转换条件（链表长度 > 8 且数组长度 > 64）

**追问**：
- Q: 为什么用红黑树不用 AVL 树？
- A: 红黑树插入删除性能更好，AVL 太严格，频繁调整

### 两种 List 对比

**概念**：ArrayList 基于动态数组，LinkedList 基于双向链表

**详细解释**：
ArrayList 随机访问快 O(1)，但插入删除需要移动元素 O(n)。
LinkedList 插入删除快 O(1)，但随机访问需要遍历 O(n)。
实际开发中 ArrayList 使用更多，因为 CPU 缓存友好。

**问题**：ArrayList 和 LinkedList 的区别？什么时候用哪个？

**答案要点**：
1. 底层：数组 vs 双向链表
2. 随机访问：ArrayList O(1) vs LinkedList O(n)
3. 插入删除：ArrayList O(n) vs LinkedList O(1)（已知节点）
4. 内存：ArrayList 连续，LinkedList 需要额外指针空间

**常见陷阱**：
- ❌ 说 LinkedList 插入删除一定快
- ✅ LinkedList 要先找到位置，找的过程是 O(n)

**追问**：
- Q: ArrayList 扩容机制？
- A: 默认初始容量 10，扩容为 1.5 倍，使用 Arrays.copyOf

### 线程安全的 HashMap

**概念**：线程安全的哈希表实现，JDK 1.8 使用 CAS + synchronized

**详细解释**：
JDK 1.7 使用分段锁 Segment，JDK 1.8 改为 CAS + synchronized。
1.8 中锁的粒度更细，只锁住链表头或红黑树根节点。
使用 volatile 保证可见性，sizeCtl 控制初始化和扩容。

**问题**：ConcurrentHashMap 如何保证线程安全？

**答案要点**：
1. JDK 1.7：Segment 分段锁，继承 ReentrantLock
2. JDK 1.8：CAS + synchronized，锁住桶头节点
3. 扩容：多线程协作扩容，transferIndex 分配任务
4. size()：使用 baseCount + CounterCell 数组累加

**对比**：
- vs Collections.synchronizedMap：后者全表锁，性能差

**常见陷阱**：
- ❌ 只说 CAS 或只说 synchronized
- ✅ 两者结合：CAS 无竞争时高效，有竞争时 synchronized

**追问**：
- Q: put 操作的完整流程？
- A: 计算 hash → CAS 插入空桶 → synchronized 处理冲突 → 检查扩容
