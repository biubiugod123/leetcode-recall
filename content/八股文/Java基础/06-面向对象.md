# 面向对象

### 类、对象与实例

**概念**：Class 是创建对象的模板（blueprint），Object / Instance 是按模板在堆上创建出来的具体对象

**一句话**：类是模板，规定对象有哪些字段（状态）和方法（行为）；用 new 按模板在堆上创建出的具体对象就是实例，每个实例有自己的一份字段。

**详细解释**：
对象 = 数据 + 对数据的操作，也就是 fields + methods。
`Person p = new Person("Tom");` 里，`Person` 是类，`new Person("Tom")` 在堆上创建对象，`p` 只是一个指向它的引用变量。
同一个类可以创建多个实例，彼此的字段互不影响；反过来，多个引用变量也可以指向同一个实例。

**问题**：类、对象、实例有什么区别？`Person p = new Person("Tom")` 这一行里分别是谁？

**答案要点**：
1. 类是模板：声明字段、构造器和方法
2. 对象 / 实例是按类创建出来的具体实体，存放在堆上
3. `p` 是引用变量，存的是对象的引用，不是对象本身
4. 每个实例有独立的实例字段；多个引用可以指向同一个实例

**常见陷阱**：
- ❌ 说"p 就是那个对象"
- ✅ p 是引用变量，对象在堆上，p 只是指向它

**追问**：
- Q: `Person p2 = p1;` 之后改 p2.name，p1.name 会变吗？
- A: 会。赋值只复制引用，p1 和 p2 指向同一个对象
- Q: 一个类可以不写构造器吗？
- A: 可以，编译器会生成无参默认构造器；但只要写了任意一个构造器，就不会再自动生成无参构造器

**代码题**：下面代码输出什么？

```java
class Person {
    String name;
    Person(String name) { this.name = name; }
}
Person p1 = new Person("Tom");
Person p2 = p1;
p2.name = "Alice";
System.out.println(p1.name);
```

- [ ] Tom
- [x] Alice
- [ ] null
- [ ] 编译错误

解析：`p2 = p1` 只复制引用，两个变量指向同一个对象，通过 p2 改字段，p1 看到的也是改后的值。

**判断题**：
- ❌ 每声明一个引用变量就会创建一个对象 —— `Person p;` 只是声明，只有 new（或反射、clone 等）才会创建对象
- ✅ 写了带参构造器后，编译器不再自动生成无参构造器 —— 此时 `new Person()` 会编译错误

### 构造器与 this

**概念**：构造器是创建对象时执行的特殊方法，名字和类名相同、没有返回类型；this 代表当前对象

**一句话**：new 对象时调用构造器完成初始化；不写构造器时编译器提供一个无参构造器，写了任意一个就不再提供；构造器可以重载，用 this(...) 调用本类其他构造器，且必须放在第一行；this.字段 用来区分同名的参数和字段。

**详细解释**：
```java
class Person {
    private String name;
    private int age;

    Person(String name) {
        this(name, 0);        // 调用另一个构造器，必须是第一条语句
    }

    Person(String name, int age) {
        this.name = name;     // this.name 是字段，name 是参数
        this.age = age;
    }
}
```
构造器没有返回类型，连 void 都不能写；写了 void 就变成一个恰好和类同名的普通方法。
构造器不能被继承，也不能被重写；子类构造器第一行默认隐式调用 super()，父类没有无参构造器时必须显式写 super(参数)。
this 的用法：区分字段和参数、调用本类构造器 this(...)、把当前对象作为参数传出去、返回 this 实现链式调用；static 方法里没有 this。

**问题**：构造器有什么特点？this 关键字有哪些用法？

**答案要点**：
1. 构造器与类同名，没有返回类型（写了 void 就成了普通方法）
2. 不写构造器时有默认无参构造器，写了任何一个就不再自动生成
3. 构造器可以重载，this(...) 调用本类其他构造器，必须在第一行
4. 子类构造器默认先调用 super()
5. this 代表当前对象：区分同名字段、链式调用、传递当前对象

**常见陷阱**：
- ❌ 给构造器加上 void 返回类型
- ✅ 那就变成普通方法了，new 的时候不会执行它
- ❌ 在构造器中间调用 this(...)
- ✅ this(...) 和 super(...) 都必须是构造器的第一条语句，两者不能同时出现

**追问**：
- Q: 父类只有带参构造器，子类构造器不写 super(...) 会怎样？
- A: 编译错误，因为子类构造器隐式调用的 super() 找不到无参构造器
- Q: 构造器可以是 private 的吗？
- A: 可以，常用于单例模式，或者只提供静态工厂方法的工具类

**代码题**：下面代码输出什么？

```java
class Person {
    String name = "default";
    void Person() {
        name = "init";
    }
}
System.out.println(new Person().name);
```

- [x] default
- [ ] init
- [ ] null
- [ ] 编译错误

解析：`void Person()` 有返回类型，所以它是一个普通方法而不是构造器；new Person() 用的是编译器生成的默认构造器，这个方法根本没被调用。

**代码题**：下面代码输出什么？

```java
class Point {
    Point() {
        this(1, 2);
        System.out.print("A ");
    }
    Point(int x, int y) {
        System.out.print("B ");
    }
}
new Point();
```

- [x] B A
- [ ] A B
- [ ] A
- [ ] B

解析：无参构造器的第一条语句 this(1, 2) 先执行带参构造器，打印 B，然后回来继续打印 A。

**判断题**：
- ✅ 构造器可以重载 —— 一个类可以有多个参数列表不同的构造器
- ❌ 构造器可以声明返回类型 void —— 写了 void 就成了普通方法，不再是构造器

### 重载与重写

**概念**：重载（Overload）是同一个类里方法名相同、参数列表不同；重写（Override）是子类重新实现父类中签名相同的方法

**一句话**：重载在编译期根据参数的声明类型选择调用哪个方法，与返回值无关；重写在运行期根据对象的实际类型决定调用哪个实现，这就是多态；static、private、final 方法都不能被重写。

**详细解释**：
重载：方法名相同，参数的个数、类型或顺序不同；只有返回值不同不构成重载（编译错误）。
重载匹配的优先级：精确匹配 → 基本类型拓宽 → 自动装箱 / 拆箱 → 可变参数。所以 f(5) 在 f(long) 和 f(Integer) 之间会选 f(long)。
重写的规则：方法名和参数列表相同；返回类型相同或是其子类（协变返回）；抛出的受检异常不能更宽；访问权限不能更小。
static 方法只会被"隐藏"，调用哪个看引用的声明类型；private 方法对子类不可见，谈不上重写；final 方法禁止重写。
重写时加上 @Override，签名写错时编译器会直接报错。

**问题**：重载和重写有什么区别？

**答案要点**：
1. 重载：同名方法，参数列表不同，与返回值无关
2. 重写：子类重新实现父类方法，方法名和参数列表必须相同
3. 重载在编译期决定，重写在运行期决定（多态）
4. 重写规则：返回类型可以协变，访问权限不能缩小，受检异常不能扩大
5. static、private、final 方法不能被重写，static 方法只会被隐藏

**对比**：
| | 重载 Overload | 重写 Override |
|---|---|---|
| 发生位置 | 同一个类（或父子类之间） | 子类与父类之间 |
| 参数列表 | 必须不同 | 必须相同 |
| 返回类型 | 无要求 | 相同或是子类型 |
| 访问权限 | 无要求 | 不能比父类更小 |
| 决定时机 | 编译期 | 运行期 |

**常见陷阱**：
- ❌ 认为只改返回类型也能构成重载
- ✅ 参数列表相同、只有返回类型不同是编译错误
- ❌ 认为子类定义了同名的 static 方法就是重写
- ✅ 那是隐藏，通过父类类型的引用调用的仍是父类版本

**追问**：
- Q: 为什么重写时访问权限不能缩小？
- A: 能通过父类引用调用的方法，换成子类对象后必须仍然能调用，否则违反里氏替换原则
- Q: @Override 注解有什么用？
- A: 让编译器检查这个方法确实重写了父类方法，方法名或参数写错会直接报错

**代码题**：下面代码输出什么？

```java
class Demo {
    static String f(long x) { return "long"; }
    static String f(Integer x) { return "Integer"; }
    static String f(int... x) { return "varargs"; }
}
System.out.println(Demo.f(5));
```

- [x] long
- [ ] Integer
- [ ] varargs
- [ ] 编译错误

解析：重载匹配先找不需要装箱、不需要可变参数的方法：int 可以拓宽为 long，所以选 f(long)；装箱和可变参数的优先级都更低。

**代码题**：下面代码输出什么？

```java
class A {
    String who() { return "A"; }
    static String kind() { return "A"; }
}
class B extends A {
    String who() { return "B"; }
    static String kind() { return "B"; }
}
A obj = new B();
System.out.println(obj.who() + obj.kind());
```

- [x] BA
- [ ] BB
- [ ] AA
- [ ] AB

解析：who() 是实例方法，被子类重写，运行时按实际类型 B 调用；kind() 是 static 方法，只会被隐藏，按引用的声明类型 A 调用。

**判断题**：
- ❌ 两个方法只有返回类型不同，也构成重载 —— 重载要求参数列表不同，只改返回类型会编译错误
- ✅ 子类重写方法时可以把 protected 改成 public —— 访问权限可以扩大，不能缩小

### 抽象类与接口

**概念**：abstract 修饰的类不能被实例化，可以包含抽象方法；接口定义一组行为契约，类通过 implements 实现

**一句话**：抽象类是"不完整的类"，可以有字段、构造器、普通方法和抽象方法，子类只能单继承它，适合复用公共实现（is-a）；接口描述能力（can-do），一个类可以实现多个接口，JDK 8 起接口还可以有 default 和 static 方法。

**详细解释**：
```java
abstract class Shape {
    abstract double area();          // 抽象方法，没有方法体
    void print() { System.out.println(area()); }
}
class Circle extends Shape {
    double r = 1;
    double area() { return Math.PI * r * r; }
}
```
含有抽象方法的类必须声明为 abstract；但抽象类可以一个抽象方法都没有（只是禁止直接 new）。
子类继承抽象类后必须实现全部抽象方法，否则自己也得声明为 abstract。
abstract 不能和 final（要求被重写 vs 禁止重写）、private（子类看不到）、static（静态方法不能被重写）一起修饰方法。
接口的方法默认 public abstract，字段默认 public static final；default 方法让接口可以新增方法而不破坏已有的实现类。
abstract 和 static、final 一样，属于非访问修饰符（Non-Access Modifier）。

**问题**：抽象类和接口有什么区别？分别在什么场景使用？

**答案要点**：
1. 抽象类不能实例化，可以有构造器、字段和普通方法
2. 一个类只能继承一个抽象类，但可以实现多个接口
3. 接口字段都是常量，方法默认 public abstract，JDK 8 起有 default / static 方法
4. 抽象类表达 is-a，复用公共代码；接口表达 can-do，定义能力
5. abstract 不能和 final、private、static 一起修饰方法

**对比**：
| | 抽象类 | 接口 |
|---|---|---|
| 关键字 | abstract class / extends | interface / implements |
| 构造器 | 有 | 没有 |
| 字段 | 任意 | 只能是 public static final 常量 |
| 方法 | 抽象方法 + 普通方法 | 抽象方法 + default / static 方法 |
| 继承数量 | 单继承 | 可以实现多个 |

**常见陷阱**：
- ❌ 认为抽象类必须包含抽象方法
- ✅ 可以一个都没有，abstract 只是禁止直接实例化
- ❌ 认为抽象类不能有构造器
- ✅ 有构造器，供子类构造时通过 super(...) 调用

**追问**：
- Q: 两个接口有同名的 default 方法，一个类同时实现它们会怎样？
- A: 编译错误，类必须重写这个方法，可以在里面用 接口名.super.方法() 指定调用哪一个

**代码题**：下面代码能编译吗？

```java
abstract class Shape {
    abstract double area();
}
Shape s = new Shape();
System.out.println(s.area());
```

- [ ] 0.0
- [x] 编译错误
- [ ] 抛出 AbstractMethodError
- [ ] null

解析：抽象类不能直接实例化，new Shape() 编译报错；要先写一个实现了 area() 的子类，再 new 子类。

**代码题**：下面代码输出什么？

```java
interface Greeter {
    default String greet() { return "Hello"; }
}
class Polite implements Greeter {
    public String greet() { return Greeter.super.greet() + ", sir"; }
}
System.out.println(new Polite().greet());
```

- [x] Hello, sir
- [ ] Hello
- [ ] , sir
- [ ] 编译错误

解析：Polite 重写了接口的 default 方法，在里面用 Greeter.super.greet() 调用接口里的默认实现，再拼上 ", sir"。

**判断题**：
- ✅ 抽象类可以有构造器 —— 子类创建对象时会通过 super(...) 调用它
- ❌ 一个方法可以同时用 abstract 和 final 修饰 —— abstract 要求子类重写，final 禁止重写，互相矛盾

### class、interface 与 enum

**概念**：class 定义类，interface 定义契约（能力），enum 定义一组固定的常量

**一句话**：class 描述"是什么"并提供实现；interface 描述"能做什么"，类用 implements 实现，一个类可以实现多个接口；enum 用于固定的取值集合，比字符串或 int 常量更类型安全。

**详细解释**：
```java
interface Flyable { void fly(); }
class Bird implements Flyable {
    public void fly() { System.out.println("fly"); }
}
enum Day { MONDAY, TUESDAY, WEDNESDAY }
```
接口里的方法默认 public abstract，字段默认 public static final；JDK 8 起可以有 default 和 static 方法。
Java 类只能单继承（extends 一个类），但可以实现多个接口。
enum 本质是继承了 java.lang.Enum 的 final 类，每个常量都是它唯一的实例，可以有字段、构造器和方法，可以直接用于 switch，用 == 比较。

**问题**：class、interface、enum 分别用来做什么？为什么用 enum 而不用字符串常量？

**答案要点**：
1. class：定义状态和行为，只能单继承
2. interface：定义契约，一个类可以实现多个接口
3. 接口方法默认 public abstract，JDK 8 起支持 default / static 方法
4. enum：固定的一组实例，编译期检查取值，不会拼错
5. enum 可以有字段和方法，能用于 switch，用 == 比较

**对比**：
| | enum | String / int 常量 |
|---|---|---|
| 取值范围 | 只能是定义好的几个实例 | 任意字符串 / 数字都能传进来 |
| 拼写错误 | 编译期报错 | 运行时才发现 |
| 能否带字段和方法 | 能 | 不能 |
| 比较方式 | 直接用 == | String 要用 equals |

**常见陷阱**：
- ❌ 用 `String day = "Monday"` 表示固定取值
- ✅ 用 enum，拼错会编译报错，取值范围也固定

**追问**：
- Q: 为什么说 enum 很适合实现单例？
- A: 枚举实例由 JVM 保证只创建一次，天然线程安全，还能防止反射和反序列化破坏单例
- Q: 一个类能同时继承类和实现接口吗？
- A: 能，写成 `class A extends B implements C, D`

**代码题**：下面代码输出什么？

```java
enum Day { MONDAY, TUESDAY, WEDNESDAY }
Day d = Day.valueOf("TUESDAY");
System.out.println(d.ordinal() + " " + d + " " + (d == Day.TUESDAY));
```

- [x] 1 TUESDAY true
- [ ] 2 TUESDAY true
- [ ] 1 TUESDAY false
- [ ] 0 Tuesday true

解析：ordinal() 是声明顺序，从 0 开始；enum 的 toString 默认返回常量名；每个常量只有一个实例，可以直接用 == 比较。

**判断题**：
- ❌ 一个 Java 类可以 extends 多个类 —— 类只能单继承，但可以实现多个接口
- ✅ 接口里定义的字段默认是 public static final —— 接口里只能有常量

### equals 与 hashCode

**概念**：equals 判断两个对象"逻辑上是否相等"，hashCode 返回对象的哈希值，供 HashMap / HashSet 定位桶

**一句话**：Object 默认的 equals 就是 ==（是不是同一个对象）；按内容判断相等而重写了 equals，就必须同时重写 hashCode，保证 equals 相等的对象 hashCode 一定相同，否则放进 HashSet / HashMap 会出现"重复"或查不到。

**详细解释**：
约定：equals 为 true → hashCode 必须相同；hashCode 相同 → equals 不一定为 true（哈希冲突）。
HashMap 查找时先用 hashCode 定位桶，再在桶里用 equals 比较；只重写 equals 的话，两个"相等"的对象 hashCode 不同，会落进不同的桶，HashSet 就会存进两份。
equals 还要满足自反性、对称性、传递性、一致性，且 x.equals(null) 必须返回 false。
常见写法：
```java
@Override
public boolean equals(Object o) {
    if (this == o) return true;
    if (!(o instanceof Person)) return false;
    Person p = (Person) o;
    return age == p.age && Objects.equals(name, p.name);
}

@Override
public int hashCode() {
    return Objects.hash(name, age);
}
```
String、Integer 等常用类都已经重写了 equals 和 hashCode。

**问题**：为什么重写 equals 时必须重写 hashCode？

**答案要点**：
1. Object.equals 默认比较引用，和 == 一样
2. 重写 equals 实现按内容比较
3. 约定：equals 相等则 hashCode 必须相等，反之不要求
4. 哈希集合先比 hashCode 再比 equals，只重写 equals 会重复存放或查不到
5. 可以用 Objects.equals / Objects.hash 简化实现

**常见陷阱**：
- ❌ 只重写 equals，不重写 hashCode
- ✅ 两者一起重写，参与计算的字段保持一致
- ❌ 用可变字段计算 hashCode，放进 HashSet 后又修改了这些字段
- ✅ 修改后 hashCode 变了，对象"留"在旧桶里，contains 和 remove 都找不到它

**追问**：
- Q: hashCode 相同的两个对象一定 equals 吗？
- A: 不一定，不同对象可能发生哈希冲突；但 equals 为 true 的对象 hashCode 必须相同

**代码题**：下面代码依次输出什么？（多行用空格隔开）

```java
class P {
    int id;
    P(int id) { this.id = id; }
    @Override
    public boolean equals(Object o) {
        return o instanceof P && ((P) o).id == id;
    }
}
Set<P> set = new HashSet<>();
set.add(new P(1));
set.add(new P(1));
System.out.println(new P(1).equals(new P(1)));
System.out.println(set.size());
```

- [x] true 2
- [ ] true 1
- [ ] false 2
- [ ] false 1

解析：equals 被重写，按 id 比较，所以为 true；但 hashCode 没重写，两个对象的哈希值不同，HashSet 认为它们是不同元素，存了 2 个。

**判断题**：
- ✅ 两个对象 equals 为 true，它们的 hashCode 必须相同 —— 这是 equals / hashCode 的基本约定
- ❌ 没有重写 equals 的类，equals 比较的是字段内容 —— Object.equals 默认就是 ==，比较的是引用
