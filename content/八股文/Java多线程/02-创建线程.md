# 创建线程

### Thread 与 Runnable

**概念**：Java 有两种创建线程的方式：继承 java.lang.Thread 并重写 run()，或者实现 java.lang.Runnable 接口再把它交给 Thread

**一句话**：Thread 类本身就实现了 Runnable；继承 Thread 会用掉唯一的继承机会，而实现 Runnable 可以继续继承别的类，同一个 Runnable 实例还能交给多个线程共享（比如多个窗口卖同一批票），Java 8 起还能直接用 lambda 写；所以一般推荐 Runnable。

**详细解释**：
Thread 的声明：`public class Thread extends Object implements Runnable`。任何线程都是 Thread 的实例，线程要执行的任务（task）通过重写 run() 实现。
Runnable：`@FunctionalInterface public interface Runnable { void run(); }`，表示"一个可以被运行的任务"；它让任务和线程分离：任务可以创建一次、到处传递、交给不同线程执行，甚至存起来以后再用。
```java
Runnable task = () -> {
    for (int i = 0; i < 10; i++) System.out.println(i);
};
Thread t = new Thread(task);
t.start();
```
Runnable VS. Thread：继承类 vs 实现接口（灵活性、代码复用）；资源共享（多个线程共享同一个 Runnable 实例）；Java 8 可以用 lambda。Simply put, we generally recommend the use of Runnable over Thread。
实际项目中更常把 Runnable / Callable 提交给线程池（ExecutorService），而不是自己 new Thread。

**问题**：创建线程有哪几种方式？为什么推荐实现 Runnable？

**答案要点**：
1. 继承 Thread，重写 run()
2. 实现 Runnable，把它传给 new Thread(runnable)
3. Runnable 不占用继承，类还能继承别的父类
4. 多个线程可以共享同一个 Runnable 实例（共享任务和数据）
5. Runnable 是函数式接口，可以用 lambda；实际开发多用线程池

**对比**：
| | 继承 Thread | 实现 Runnable |
|---|---|---|
| 继承 | 用掉唯一的父类 | 还能继承别的类 |
| 任务与线程 | 绑在一起 | 分离，任务可复用 |
| 共享数据 | 每个线程对象各有一份字段 | 多个线程可以共享同一个任务对象 |
| lambda | 不行 | 可以 |

**常见陷阱**：
- ❌ 实现了 Runnable 就直接调用 task.run()，以为启动了线程
- ✅ 要 new Thread(task).start() 才会创建新线程

**追问**：
- Q: Runnable 和 Callable 有什么区别？
- A: Callable 的 call() 有返回值、可以抛出 checked 异常，一般配合线程池和 Future 使用；Runnable 的 run() 没有返回值，也不能抛 checked 异常

**代码题**：下面代码输出什么？

```java
class Task implements Runnable {
    int count = 0;
    public void run() { count++; }
}
Task task = new Task();
Thread t1 = new Thread(task);
Thread t2 = new Thread(task);
t1.start();
t1.join();
t2.start();
t2.join();
System.out.println(task.count);
```

- [x] 2
- [ ] 1
- [ ] 0
- [ ] 编译错误

解析：两个线程共享同一个 Runnable 实例，各执行一次 run()，count 被加了两次；这里用 join 让它们先后执行，所以结果确定是 2。

**代码题**：下面代码输出什么？

```java
class Worker extends Thread {
    int count = 0;
    public void run() { count++; }
}
Worker w1 = new Worker();
Worker w2 = new Worker();
w1.start();
w2.start();
w1.join();
w2.join();
System.out.println(w1.count + " " + w2.count);
```

- [x] 1 1
- [ ] 2 2
- [ ] 2 0
- [ ] 0 0

解析：继承 Thread 时，每个线程对象各有自己的 count 字段，各自加一次，互不影响。

**判断题**：
- ✅ Thread 类本身实现了 Runnable 接口 —— 声明是 class Thread extends Object implements Runnable
- ❌ 实现 Runnable 的类不能再继承其他类 —— 实现接口不占用继承，还可以 extends 一个父类

### start() 与 run()

**概念**：调用 start() 会创建一个新线程，并在新线程里执行一次 run()；直接调用 run() 只是在当前线程里执行一个普通方法，不会创建新线程

**一句话**：start() 定义在 Thread 类里，同一个线程对象只能 start 一次，再调用抛 IllegalThreadStateException；run() 定义在 Runnable 接口里、必须被重写，可以调用任意多次，每次都在调用它的那个线程里同步执行。

**详细解释**：
When a program calls the start() method, an actual thread is created and then the run() method is executed once in that new thread。
When a program calls the run() method, no new thread will be created；run() will be executed as a normal method call on the current calling thread itself；Multithreading does not necessarily take place。
Interview Question: start() VS. run()：Behavior（新线程 vs 当前线程）；Multiple invocation（start 只能一次，run 可以多次）；Definition（start() 在 java.lang.Thread，run() 在 java.lang.Runnable，必须重写）。
课件例子：p.start() 之后再 p.run(); p.run();，结果是新线程打印一遍、main 线程打印两遍，并且输出会交错。
start() 之后线程进入 RUNNABLE 状态，什么时候真正执行由线程调度器决定。

**问题**：start() 和 run() 有什么区别？一个线程能 start 两次吗？

**答案要点**：
1. start() 创建新线程，在新线程里执行 run()
2. 直接调用 run() 不创建线程，在当前线程里同步执行
3. start() 只能调用一次，第二次抛 IllegalThreadStateException
4. run() 可以调用多次
5. start() 定义在 Thread 类，run() 定义在 Runnable 接口

**对比**：
| | start() | run() |
|---|---|---|
| 是否创建新线程 | 是 | 否 |
| 在哪个线程执行 | 新线程 | 当前调用线程 |
| 调用次数 | 只能一次 | 任意多次 |
| 定义位置 | Thread 类 | Runnable 接口 |

**常见陷阱**：
- ❌ 调用 t.run() 以为启动了一个新线程
- ✅ run() 就是普通方法调用，代码仍在当前线程里同步执行
- ❌ 线程结束后想再 start() 一次复用它
- ✅ 线程对象只能启动一次，要重新执行任务得创建新的 Thread 或用线程池

**追问**：
- Q: 为什么不能直接调用 run() 来实现多线程？
- A: 创建线程、交给操作系统调度是 start() 里（native 方法 start0）完成的；直接调 run() 跳过了这一步，只是一次普通方法调用

**代码题**：下面代码输出什么？

```java
Thread t = new Thread(() -> System.out.print(Thread.currentThread().getName() + " "), "worker");
t.run();
t.start();
t.join();
System.out.println();
```

- [x] main worker
- [ ] worker worker
- [ ] main main
- [ ] worker main

解析：t.run() 是普通方法调用，在 main 线程里执行，打印 main；t.start() 创建了名为 worker 的新线程，在新线程里打印 worker；join 保证它打印完再换行。

**代码题**：下面代码运行结果是什么？

```java
Thread t = new Thread(() -> { });
t.start();
t.join();
t.start();
System.out.println("done");
```

- [ ] done
- [ ] 什么也不输出
- [x] 抛出 IllegalThreadStateException
- [ ] 编译错误

解析：一个线程对象只能 start 一次；第二次调用 start() 时线程已经不是 NEW 状态，抛出 IllegalThreadStateException。

**代码题**：下面代码输出什么？

```java
int[] n = {0};
Thread t = new Thread(() -> n[0]++);
t.run();
t.run();
System.out.println(n[0] + " " + t.getState());
```

- [x] 2 NEW
- [ ] 2 TERMINATED
- [ ] 1 NEW
- [ ] 抛出 IllegalThreadStateException

解析：run() 可以调用多次，每次都在 main 线程里执行一遍任务，n[0] 变成 2；因为从没调用 start()，线程对象仍处于 NEW 状态。

**判断题**：
- ✅ 直接调用 run() 不会创建新线程 —— 它在当前调用线程里作为普通方法执行
- ❌ 同一个 Thread 对象可以多次调用 start() —— 第二次会抛 IllegalThreadStateException

### main 线程与守护线程

**概念**：程序启动时 JVM 创建 main 线程并在其中调用 main()；守护线程（daemon thread）是为用户线程提供后台服务的低优先级线程，所有用户线程结束后 JVM 会直接终止守护线程

**一句话**：main 线程是每个 Java 程序的默认线程，JVM 还会创建一些看不见的后台线程（比如 GC）；用 setDaemon(true) 把线程设为守护线程，必须在 start() 之前设置；只要还有用户线程在运行，JVM 就不会退出，而守护线程不会阻止 JVM 退出。

**详细解释**：
Main Thread：main() method – entry point of every java program；main thread – default thread of every java program；When the execution of Java program starts, the JVM creates the main thread and calls the program's main() method within that thread；Programmers can always take control of the main thread；JVM also creates some invisible threads for JVM housekeeping tasks。
Daemon Threads（课件标题写成 Demon）：A low priority thread provides services to user threads for background supporting tasks；Its life depend on the mercy of user thread：when the user thread dies, JVM terminates this thread immediately, regardless of if its daemon threads are still executing。
How to create：public void setDaemon(boolean status)；public boolean isDaemon()。
例子：MMORPG 游戏用守护线程加载地图，用户线程处理角色动作；退出游戏后没必要继续加载地图。
新线程默认继承创建者的 daemon 属性，main 是用户线程，所以默认都是用户线程；守护线程里的 finally 不保证执行，不要用它做写文件等需要收尾的工作。

**问题**：什么是守护线程？它和用户线程有什么区别？

**答案要点**：
1. main 线程由 JVM 创建，执行 main() 方法
2. 守护线程为用户线程提供后台服务，比如 GC 线程
3. 所有用户线程结束后，JVM 退出，守护线程被直接终止
4. 用 setDaemon(true) 设置，必须在 start() 之前
5. 新线程默认继承创建它的线程的 daemon 属性

**对比**：
| | 用户线程 | 守护线程 |
|---|---|---|
| 是否阻止 JVM 退出 | 是 | 否 |
| 默认 | main 创建的线程默认是用户线程 | 需要 setDaemon(true) |
| 适合做 | 业务逻辑 | 后台辅助任务（GC、监控、预加载） |
| finally 是否保证执行 | 正常结束时会 | JVM 退出时可能来不及执行 |

**常见陷阱**：
- ❌ 线程启动之后再调用 setDaemon(true)
- ✅ 运行中的线程调用 setDaemon 会抛 IllegalThreadStateException，必须在 start() 前设置
- ❌ 在守护线程里写文件、提交事务等收尾工作
- ✅ JVM 退出时守护线程会被直接终止，工作可能做到一半

**追问**：
- Q: main 方法执行完了，JVM 一定会退出吗？
- A: 不一定，只要还有用户线程（非守护线程）在运行，JVM 就会继续运行，直到它们都结束

**代码题**：下面代码输出什么？

```java
Thread t = new Thread(() -> { });
System.out.println(Thread.currentThread().getName() + " " + Thread.currentThread().isDaemon() + " " + t.isDaemon());
```

- [x] main false false
- [ ] main true false
- [ ] main false true
- [ ] Thread-0 false false

解析：当前线程是 JVM 创建的 main 线程，它是用户线程；新线程默认继承创建者的 daemon 属性，所以也不是守护线程。

**代码题**：下面代码运行结果是什么？

```java
Thread t = new Thread(() -> {
    try { Thread.sleep(1000); } catch (InterruptedException e) { }
});
t.start();
t.setDaemon(true);
System.out.println("daemon set");
```

- [ ] daemon set
- [ ] 什么也不输出
- [x] 抛出 IllegalThreadStateException
- [ ] 编译错误

解析：线程已经启动并且还在运行（在 sleep），这时再调用 setDaemon 会抛 IllegalThreadStateException；必须在 start() 之前设置。

**判断题**：
- ✅ 所有用户线程结束后，JVM 会直接终止仍在运行的守护线程 —— 守护线程不会阻止 JVM 退出
- ❌ 可以在线程运行过程中随时调用 setDaemon(true) 把它变成守护线程 —— 必须在 start() 之前调用
