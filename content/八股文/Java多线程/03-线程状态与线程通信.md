# 线程状态与线程通信

### 线程的生命周期

**概念**：线程的状态由 JVM 的线程调度器管理，共有 NEW、RUNNABLE、BLOCKED、WAITING、TIMED_WAITING、TERMINATED 六种

**一句话**：new 出来是 NEW，start() 后是 RUNNABLE（包括正在运行和等 CPU）；等 synchronized 的锁是 BLOCKED，join() / wait() 无限期等待是 WAITING，sleep() / wait(ms) / join(ms) 限时等待是 TIMED_WAITING；被 notify、I/O 完成、sleep 到期、join 完成后回到 RUNNABLE；run() 执行完或抛出未捕获异常后是 TERMINATED。

**详细解释**：
States of thread — managed by Thread Scheduler of JVM：
NEW — just created but not started
RUNNABLE — created, started, and able to run（running：正在运行，也属于 RUNNABLE）
BLOCKED、WAITING、TIMED_WAITING — created and started but unable to run because it is waiting for some event to occur：BLOCKED 等待获取锁（比如 synchronized）；WAITING 无限期等待（join()、wait()）；TIMED_WAITING 等待指定的时间（sleep()、wait(ms)、join(ms)）
TERMINATED — thread has finished or is stopped
状态转换：new → NEW；start() → RUNNABLE；I/O、sleep()、join()、wait → 阻塞类状态；notify()、notifyAll()、I/O Complete、sleep expired、join complete → 回到 RUNNABLE；结束 → TERMINATED。
课件图里写的 terminate() 只表示"线程结束"，Java 里没有这个方法；已废弃的 stop() 也不应该使用。
可以用 t.getState() 查看线程当前的状态。

**问题**：Java 线程有哪几种状态？它们之间怎么转换？

**答案要点**：
1. NEW：创建但还没 start
2. RUNNABLE：start 之后可运行，包括正在运行
3. BLOCKED：等待获取 synchronized 锁
4. WAITING / TIMED_WAITING：无限期等待（join、wait）/ 限时等待（sleep、wait(ms)、join(ms)）
5. TERMINATED：run() 执行完或抛出未捕获异常

**对比**：
| 状态 | 进入方式 | 离开方式 |
|---|---|---|
| NEW | new Thread() | start() |
| RUNNABLE | start()、等待结束、拿到锁 | 阻塞、等待、执行完 |
| BLOCKED | 竞争 synchronized 锁失败 | 拿到锁 |
| WAITING | wait()、join() | notify / notifyAll、被 join 的线程结束 |
| TIMED_WAITING | sleep(ms)、wait(ms)、join(ms) | 超时、被唤醒 |
| TERMINATED | run() 结束 | 不能再启动 |

**常见陷阱**：
- ❌ 认为 Java 线程有一个独立的 RUNNING 状态
- ✅ Thread.State 里没有 RUNNING，正在运行和等待 CPU 都属于 RUNNABLE
- ❌ 把 BLOCKED 和 WAITING 混为一谈
- ✅ BLOCKED 是在等锁；WAITING 是主动等待别的线程的通知或结束

**追问**：
- Q: TERMINATED 状态的线程能重新 start 吗？
- A: 不能，会抛 IllegalThreadStateException；线程对象只能启动一次

**代码题**：下面代码输出什么？

```java
Thread t = new Thread(() -> {
    try { Thread.sleep(1000); } catch (InterruptedException e) { }
});
System.out.print(t.getState() + " ");
t.start();
Thread.sleep(200);
System.out.print(t.getState() + " ");
t.join();
System.out.println(t.getState());
```

- [x] NEW TIMED_WAITING TERMINATED
- [ ] NEW RUNNABLE TERMINATED
- [ ] NEW WAITING TERMINATED
- [ ] RUNNABLE TIMED_WAITING TERMINATED

解析：start 之前是 NEW；子线程在 sleep(1000) 期间处于限时等待 TIMED_WAITING；join 等它结束后是 TERMINATED。

**判断题**：
- ✅ 线程在等待获取 synchronized 锁时处于 BLOCKED 状态 —— 拿到锁后回到 RUNNABLE
- ❌ 调用 sleep(1000) 的线程处于 WAITING 状态 —— 有时间限制的等待是 TIMED_WAITING

### sleep 与 join

**概念**：Thread.sleep(ms) 让当前线程暂停指定的毫秒数；t.join() 让当前线程等待线程 t 执行完毕，join(timeout) 最多等待 timeout 毫秒

**一句话**：sleep 是 Thread 的静态方法，作用于"当前线程"，暂停期间不会释放已经持有的锁，可能被 interrupt 打断而抛出 InterruptedException；join 常用来让 main 等子线程算完再继续，join(timeout) 超时后不管子线程有没有结束都会继续往下走。

**详细解释**：
Thread.sleep()：causes the current thread to suspend execution for a specified period；Thread.sleep(x) makes the thread sleep for x milliseconds。
Thread.join()：The method allows one thread to wait for the completion of another；例如在 main 线程里创建 Thread t，调用 t.join() 会让 main 线程等到 t 执行完；join(timeout)：main 最多等 timeout 毫秒，之后如果新线程还在运行，main 也会继续执行。
sleep 和 join 都会抛出 checked 异常 InterruptedException，调用时必须处理。
t.sleep(1000) 这种写法虽然能编译，但睡眠的仍然是当前线程而不是 t，容易误导。

**问题**：sleep() 和 join() 分别有什么作用？

**答案要点**：
1. sleep(ms) 让当前线程暂停指定时间，进入 TIMED_WAITING
2. sleep 不释放已经持有的锁
3. t.join() 让当前线程等 t 结束，进入 WAITING
4. join(timeout) 最多等 timeout 毫秒，超时后继续执行
5. 两者都声明了 InterruptedException，需要处理

**对比**：
| | sleep(ms) | join() |
|---|---|---|
| 属于 | Thread 的静态方法 | Thread 的实例方法 |
| 作用 | 当前线程暂停一段时间 | 当前线程等另一个线程结束 |
| 状态 | TIMED_WAITING | WAITING（join(ms) 是 TIMED_WAITING） |
| 是否释放锁 | 不释放 | 内部基于 wait，释放的是被 join 线程对象的锁 |

**常见陷阱**：
- ❌ 写 t.sleep(1000) 以为让线程 t 睡眠
- ✅ sleep 是静态方法，睡眠的是当前线程
- ❌ 在持有锁时 sleep，以为别的线程能趁机拿到锁
- ✅ sleep 不释放锁，其他等这把锁的线程会一直 BLOCKED

**追问**：
- Q: 怎么让三个线程 T1、T2、T3 按顺序执行完？
- A: 依次 start 并 join：T1.start(); T1.join(); T2.start(); T2.join(); ...，或者在 T2 里 join T1、T3 里 join T2

**代码题**：下面代码输出什么？

```java
Thread t = new Thread(() -> System.out.print("child "));
t.start();
t.join();
System.out.println("main");
```

- [x] child main
- [ ] main child
- [ ] main
- [ ] 顺序不确定

解析：t.join() 让 main 线程等 t 执行完，所以 child 一定先于 main 打印。

**判断题**：
- ✅ Thread.sleep() 不会释放当前线程持有的锁 —— 只是暂停执行，锁仍被占着
- ❌ join(timeout) 超时后，会强制终止那个还没结束的线程 —— 只是当前线程不再等待，那个线程继续运行

### wait、notify 与 notifyAll

**概念**：wait()、notify()、notifyAll() 是 Object 的方法，用于线程间协作：线程在某个对象上 wait 并释放锁，其他线程在同一个对象上 notify 唤醒它

**一句话**：三个方法都必须在 synchronized 里、对同一个锁对象调用，否则抛 IllegalMonitorStateException；wait 会释放锁并进入 WAITING，被唤醒后要重新拿到锁才能继续；notify 唤醒一个等待线程，notifyAll 唤醒所有；典型场景是生产者-消费者：缓冲区满了生产者等，空了消费者等。

**详细解释**：
Lock in Java：每个资源有一把锁，只有持有锁的线程才能访问资源；Synchronization is a mechanism to control access to shared resources when multiple threads are running concurrently。
Producer and Consumer：Buffer 是共享存储；Producer 往 buffer 里放数据，满了就等消费者；Consumer 从 buffer 取数据，空了就等生产者。
Object.wait()：让当前线程等待，直到其他线程在同一个对象上调用 notify() / notifyAll()；必须在 synchronized 上下文中调用，否则抛 IllegalMonitorStateException；调用 wait() 时会释放这个对象的锁并进入 WAITING。
Object.notify()：唤醒一个在该对象 monitor 上等待的线程，被唤醒的线程要重新获得锁后才继续执行。
Object.notifyAll()：唤醒所有在该对象 monitor 上等待的线程。
wait 要放在 while 循环里检查条件，防止虚假唤醒（spurious wakeup）。

**问题**：wait() 和 sleep() 有什么区别？为什么 wait / notify 必须在 synchronized 里调用？

**答案要点**：
1. wait / notify / notifyAll 是 Object 的方法，任何对象都可以当锁
2. 必须在 synchronized 里、对同一个锁对象调用，否则抛 IllegalMonitorStateException
3. wait 释放锁并进入 WAITING，sleep 不释放锁
4. notify 唤醒一个，notifyAll 唤醒全部，被唤醒后要重新竞争锁
5. wait 写在 while 循环里检查条件，防止虚假唤醒

**对比**：
| | wait() | sleep() |
|---|---|---|
| 属于 | Object 的实例方法 | Thread 的静态方法 |
| 调用前提 | 必须持有该对象的锁 | 没有要求 |
| 是否释放锁 | 释放 | 不释放 |
| 如何醒来 | notify / notifyAll、超时、中断 | 时间到、中断 |

**常见陷阱**：
- ❌ 用 if 判断条件后 wait
- ✅ 用 while：被唤醒后条件可能已经被别的线程改变，要重新检查
- ❌ 在没有持有锁的地方调用 notify
- ✅ 必须在 synchronized(lock) 里调用 lock.notify()

**追问**：
- Q: notify 和 notifyAll 应该用哪个？
- A: 一般用 notifyAll 更安全；notify 只唤醒一个线程，如果唤醒的不是能继续执行的那个，可能导致所有线程都在等待

**代码题**：下面代码运行结果是什么？

```java
Object lock = new Object();
lock.wait();
System.out.println("woke up");
```

- [ ] woke up
- [ ] 程序一直等待
- [x] 抛出 IllegalMonitorStateException
- [ ] 编译错误

解析：调用 wait() 前必须持有这个对象的锁（在 synchronized(lock) 里），否则运行时抛 IllegalMonitorStateException。

**代码题**：下面代码输出什么？

```java
Object lock = new Object();
boolean[] ready = {false};
Thread consumer = new Thread(() -> {
    synchronized (lock) {
        while (!ready[0]) {
            try { lock.wait(); } catch (InterruptedException e) { }
        }
        System.out.print("consumed ");
    }
});
consumer.start();
synchronized (lock) {
    System.out.print("produced ");
    ready[0] = true;
    lock.notify();
}
consumer.join();
System.out.println();
```

- [x] produced consumed
- [ ] consumed produced
- [ ] produced
- [ ] 顺序不确定

解析：消费者如果先拿到锁，发现 ready 为 false 就 wait 并释放锁；main 拿到锁后打印 produced、设置标志并 notify。如果 main 先拿到锁，消费者之后进入时 ready 已是 true，不用等。两种情况输出都是 produced consumed。

**判断题**：
- ✅ 调用 wait() 的线程会释放它持有的这个对象的锁 —— 这样其他线程才能进入 synchronized 并 notify 它
- ❌ notify() 被调用后，被唤醒的线程立即继续执行，不需要重新获取锁 —— 必须等通知方退出 synchronized、自己重新拿到锁后才能继续

### interrupt 与 InterruptedException

**概念**：Thread.interrupt() 用来通知一个线程停止它正在做的事，它不会强制停止线程，只是设置中断标志；线程处于 sleep、wait、join 等阻塞状态时被中断，会抛出 InterruptedException

**一句话**：中断是一种协作机制：被中断的线程要自己检查 isInterrupted() 或捕获 InterruptedException 来决定怎么结束；InterruptedException 是 checked 异常，而 Runnable 的 run() 没有声明它，所以只能在 run() 里面处理；抛出异常时中断标志会被清除，常见做法是在 catch 里再调用一次 interrupt() 恢复它。

**详细解释**：
Thread.interrupt()：A method used to signal a thread to stop what it's doing；It does not forcibly stop the thread — it simply sets an interrupt flag；If the thread is in a blocking state (sleep(), wait(), join()), it will throw an InterruptedException。
InterruptedException：A checked exception thrown when a thread is interrupted while it's in a blocking state；Catching this exception is often a signal to gracefully stop or exit the current thread。
Runnable and InterruptedException：The Runnable interface run() method does not declare InterruptedException；所以用 Runnable（或 lambda）时不能把它往外抛，必须在 run() 里处理。
查询方法：t.isInterrupted() 查看标志、不清除；静态方法 Thread.interrupted() 查看当前线程的标志并清除它。
不要用已废弃的 stop() 强行停止线程，它会让锁保护的数据处于不一致状态。

**问题**：怎么正确地停止一个线程？interrupt() 会立即停止线程吗？

**答案要点**：
1. interrupt() 只设置中断标志，不会强制停止线程
2. 线程在 sleep / wait / join 时被中断会抛 InterruptedException
3. 线程自己检查 isInterrupted() 或捕获异常后优雅退出
4. Runnable.run() 不能抛 checked 异常，必须在内部处理 InterruptedException
5. 抛出异常会清除中断标志，捕获后常用 Thread.currentThread().interrupt() 恢复

**常见陷阱**：
- ❌ catch (InterruptedException e) {} 什么都不做
- ✅ 吞掉异常会丢失中断信号，应该退出或恢复中断标志
- ❌ 以为调用 interrupt() 后线程马上就停了
- ✅ 线程不检查标志、也不处于阻塞状态时，会照常运行下去

**追问**：
- Q: isInterrupted() 和 Thread.interrupted() 有什么区别？
- A: isInterrupted() 是实例方法，只读取标志；interrupted() 是静态方法，读取当前线程的标志并把它清除

**代码题**：下面代码输出什么？

```java
Thread t = new Thread(() -> {
    try {
        Thread.sleep(5000);
        System.out.print("woke ");
    } catch (InterruptedException e) {
        System.out.print("interrupted ");
    }
});
t.start();
t.interrupt();
t.join();
System.out.println("done");
```

- [x] interrupted done
- [ ] woke done
- [ ] done
- [ ] woke interrupted done

解析：子线程在 sleep 时被中断（即使中断发生在 sleep 之前，进入 sleep 时也会立即抛出），捕获 InterruptedException 打印 interrupted；不用等 5 秒。

**代码题**：下面代码输出什么？

```java
Thread.currentThread().interrupt();
System.out.println(Thread.currentThread().isInterrupted() + " " + Thread.interrupted() + " " + Thread.currentThread().isInterrupted());
```

- [x] true true false
- [ ] true true true
- [ ] false false false
- [ ] true false false

解析：interrupt() 设置了中断标志；isInterrupted() 读取但不清除，为 true；Thread.interrupted() 读取到 true 并清除标志；之后再读就是 false。

**判断题**：
- ✅ interrupt() 不会强制终止线程，只是设置中断标志 —— 线程需要自己响应中断
- ❌ Runnable 的 run() 方法可以声明 throws InterruptedException —— run() 签名没有声明 checked 异常，必须在内部处理
