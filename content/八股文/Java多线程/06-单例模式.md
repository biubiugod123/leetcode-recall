# 单例模式

### 单例模式：饿汉、懒汉与双重检查锁

**概念**：单例（Singleton）是保证一个类同一时间只有一个实例的设计模式；实现方式有饿汉式（类初始化时创建）和懒汉式（第一次调用 getInstance() 时创建）

**一句话**：单例的关键是 private 构造器 + 静态的 getInstance()；饿汉式天然线程安全但不管用不用都会创建；懒汉式在多线程下可能创建出多个实例，可以给 getInstance 加 synchronized（简单但每次都加锁），或者用双重检查锁（instance 必须 volatile）；还可以用静态内部类或 enum 实现。

**详细解释**：
Singleton is a design pattern which ensures that one instance of the singleton class exist at a time。
Two ways：Eager initialization – The instance is initialized at the time of creation；Lazy initialization – The instance is initialized when the first time getInstance() method is called。
What could be the problem in multithreading environment？两个线程同时判断 instance == null 都为 true，会各自 new 出一个实例。
How to ensure the thread safety？2 approaches：Double check locking for lazily initialized Singleton classes；Synchronized getInstance() method。
```java
public class Singleton {
    private static volatile Singleton instance;
    private Singleton() { }
    public static Singleton getInstance() {
        if (instance == null) {                  // 第一次检查：已创建就不加锁
            synchronized (Singleton.class) {
                if (instance == null) {          // 第二次检查：防止重复创建
                    instance = new Singleton();
                }
            }
        }
        return instance;
    }
}
```
为什么要 volatile：new Singleton() 分为分配内存、初始化、把引用赋给 instance，可能被重排成先赋值后初始化，别的线程会拿到还没初始化完的对象。
Why do we need lazy initialization？实例创建代价大、又不一定用到时，延迟到真正需要时再创建，节省启动时间和内存。
饿汉式的"创建时机"是类初始化时，类在第一次被主动使用（比如调用它的静态方法）时才初始化。

**问题**：单例模式有哪些实现方式？懒汉式怎么保证线程安全？双重检查锁为什么要加 volatile？

**答案要点**：
1. 核心：private 构造器 + 静态 getInstance() 返回唯一实例
2. 饿汉式：类初始化时创建，线程安全，但可能创建了用不到的实例
3. 懒汉式：第一次使用时创建，多线程下可能创建多个实例
4. 线程安全的懒汉：synchronized getInstance（每次加锁慢）或双重检查锁（instance 要 volatile）
5. 静态内部类、enum 也是线程安全的写法，enum 还能防反射和反序列化

**对比**：
| 写法 | 懒加载 | 线程安全 | 特点 |
|---|---|---|---|
| 饿汉式 | 否 | 是 | 最简单 |
| 懒汉式 | 是 | 否 | 多线程会创建多个实例 |
| synchronized getInstance | 是 | 是 | 每次调用都加锁，慢 |
| 双重检查锁 + volatile | 是 | 是 | 只有第一次创建时加锁 |
| 静态内部类 | 是 | 是 | 利用类加载机制 |
| enum | 否 | 是 | 防反射、防反序列化 |

**常见陷阱**：
- ❌ 双重检查锁的 instance 不加 volatile
- ✅ 指令重排可能让其他线程拿到未初始化完成的对象
- ❌ 认为饿汉式的实例在程序一启动时就创建
- ✅ 是在类初始化时创建，类第一次被使用时才初始化

**追问**：
- Q: 反射能破坏单例吗？怎么防？
- A: 能，setAccessible(true) 后可以调用 private 构造器；可以在构造器里判断实例已存在就抛异常，或者直接用 enum 单例

**代码题**：下面代码输出什么？

```java
class Singleton {
    private static Singleton instance;
    private Singleton() { System.out.print("create "); }
    static Singleton getInstance() {
        if (instance == null) instance = new Singleton();
        return instance;
    }
}
System.out.print("start ");
Singleton a = Singleton.getInstance();
Singleton b = Singleton.getInstance();
System.out.println(a == b);
```

- [x] start create true
- [ ] create start true
- [ ] start create create false
- [ ] start create false

解析：懒汉式在第一次调用 getInstance() 时才创建实例，所以 start 先打印；第二次调用直接返回同一个实例，a == b 为 true。

**代码题**：下面代码输出什么？

```java
class Eager {
    private static final Eager INSTANCE = new Eager();
    private Eager() { System.out.print("create "); }
    static Eager getInstance() { return INSTANCE; }
    static void hello() { System.out.print("hello "); }
}
System.out.print("start ");
Eager.hello();
Eager.getInstance();
System.out.println("end");
```

- [x] start create hello end
- [ ] create start hello end
- [ ] start hello create end
- [ ] start hello end

解析：饿汉式的实例在类初始化时创建；第一次调用 Eager.hello() 触发了类初始化，先执行静态字段的 new Eager() 打印 create，再执行 hello()；之后 getInstance() 不再创建。

**代码题**：下面代码能编译吗？

```java
class Singleton {
    private static final Singleton INSTANCE = new Singleton();
    private Singleton() { }
    static Singleton getInstance() { return INSTANCE; }
}
Singleton s = new Singleton();
System.out.println(s == Singleton.getInstance());
```

- [ ] true
- [ ] false
- [x] 编译错误
- [ ] 抛出 IllegalStateException

解析：构造器是 private 的，其他类不能直接 new，编译报错；这正是单例阻止外部创建实例的方式。

**判断题**：
- ✅ 双重检查锁实现单例时，instance 字段需要用 volatile 修饰 —— 防止指令重排导致拿到未初始化完成的对象
- ❌ 不加任何同步的懒汉式单例在多线程下也只会创建一个实例 —— 多个线程可能同时通过 null 判断，各自创建实例
