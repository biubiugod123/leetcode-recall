# 异常体系

### 异常与 Throwable 体系

**概念**：异常是程序运行时发生的、打断正常执行流程的意外事件；Java 里所有异常和错误的父类是 Throwable，它下面分成 Error 和 Exception

**一句话**：Throwable 分两支：Error 是 JVM 级别的严重问题（OutOfMemoryError、StackOverflowError），程序不应该尝试恢复；Exception 是程序可以处理的问题，又分成 RuntimeException（unchecked）和其他 Exception（checked，比如 IOException）。

**详细解释**：
定义：An exception is an unwanted or unexpected event, which occurs during the execution of a program (at runtime), that disrupts the normal flow of the program's instructions.
常见场景：数组越界（ArrayIndexOutOfBoundsException）、除以 0（ArithmeticException）、文件不存在（FileNotFoundException）、线程被中断（InterruptedException）、I/O 失败（IOException）、对 null 解引用（NullPointerException）。
Error：indicates serious problem that a reasonable application should not try to recover from，大多在致命情况下由 JVM 抛出。
体系：Object → Throwable → Error（OutOfMemoryError、StackOverflowError、LinkageError）/ Exception → RuntimeException（IllegalArgumentException → NumberFormatException、ArithmeticException、IndexOutOfBoundsException → ArrayIndexOutOfBoundsException）/ IOException（FileNotFoundException、SocketException）。

**问题**：说一下 Java 的异常体系，Exception 和 Error 有什么区别？

**答案要点**：
1. Throwable 是所有异常和错误的父类
2. Error：JVM 级别的严重问题，如 OutOfMemoryError、StackOverflowError，不应该捕获处理
3. Exception：程序可以处理的问题
4. Exception 分为 RuntimeException（unchecked）和其他 Exception（checked）
5. 异常发生在运行时，会打断正常的执行流程

**对比**：
| | Error | Exception |
|---|---|---|
| 含义 | 严重问题，程序无法恢复 | 程序可以处理的问题 |
| 谁抛出 | 大多是 JVM | JVM 或程序代码 |
| 例子 | OutOfMemoryError、StackOverflowError | IOException、NullPointerException |
| 是否应该 catch | 不应该 | 应该处理 |

**常见陷阱**：
- ❌ 用 catch (Throwable t) 或 catch (Error e) 兜住一切
- ✅ Error 说明 JVM 已经处于异常状态，捕获后程序也很难正常运行，应该让它暴露出来
- ❌ 认为 NumberFormatException 是 checked 异常
- ✅ 它继承自 IllegalArgumentException → RuntimeException，是 unchecked

**追问**：
- Q: 无限递归会抛什么？是 Exception 还是 Error？
- A: StackOverflowError，属于 Error

**代码题**：下面代码依次输出什么？（多行用空格隔开）

```java
Throwable a = new NumberFormatException();
Throwable b = new StackOverflowError();
System.out.println(a instanceof RuntimeException);
System.out.println(b instanceof Exception);
System.out.println(b instanceof Throwable);
```

- [x] true false true
- [ ] false false true
- [ ] true true true
- [ ] true false false

解析：NumberFormatException → IllegalArgumentException → RuntimeException；StackOverflowError 是 Error，不是 Exception，但它们都继承 Throwable。

**判断题**：
- ✅ Throwable 是所有异常和错误的父类 —— Error 和 Exception 都继承自 Throwable
- ❌ StackOverflowError 是 RuntimeException 的子类 —— 它是 Error 的子类（VirtualMachineError），和 Exception 平级

### Checked 与 Unchecked 异常

**概念**：继承 RuntimeException 的是 unchecked 异常，运行时由 JVM 检查；其他 Exception 是 checked 异常，编译器在编译时检查，程序员必须处理

**一句话**：checked 异常（IOException、SQLException、InterruptedException）必须用 try-catch 处理或者在方法上用 throws 声明，否则编译不过；unchecked 异常（NullPointerException、ArrayIndexOutOfBoundsException）不强制处理，通常代表程序 bug；Error 也不强制处理。

**详细解释**：
Unchecked exception：Any classes extends RuntimeException；checked by the JVM at run time；e.g. ArrayIndexOutOfBoundsException、NullPointerException。
Checked exception：Any other Exceptions that are not unchecked exception；checked by the compiler at compile time；Programmers are required to handle any possible checked exceptions；e.g. IOException、SQLException、InterruptedException。
选择原则：调用方有能力恢复的外部问题（文件不存在、网络断了）用 checked；编程错误（参数非法、空指针）用 unchecked。
Spring 等框架倾向于把 checked 异常包装成 unchecked，避免层层 throws。

**问题**：checked 异常和 unchecked 异常有什么区别？各举几个例子

**答案要点**：
1. unchecked：RuntimeException 及其子类，运行时检查
2. checked：其他 Exception，编译时检查
3. checked 必须 try-catch 或 throws，否则编译错误
4. unchecked 不强制处理，通常是程序 bug
5. 例子：IOException / SQLException 是 checked；NPE / 越界 / 除 0 是 unchecked

**对比**：
| | Checked | Unchecked |
|---|---|---|
| 父类 | Exception（不是 RuntimeException） | RuntimeException |
| 检查时机 | 编译时 | 运行时 |
| 必须处理 | 是 | 否 |
| 典型原因 | 外部环境（文件、网络、数据库） | 程序 bug |
| 例子 | IOException、SQLException、InterruptedException | NullPointerException、ArithmeticException |

**常见陷阱**：
- ❌ 认为 checked 异常是"运行时才检查"的
- ✅ checked 是编译器检查的；运行时才暴露、编译器不管的是 unchecked
- ❌ 认为 Error 是 checked
- ✅ Error 和 RuntimeException 一样都不强制处理

**追问**：
- Q: 为什么 InterruptedException 是 checked 异常？
- A: 线程被中断是可以预期、也应该处理的情况（比如结束任务、恢复中断标志），所以强制调用方面对它

**代码题**：下面代码能编译吗？

```java
class T {
    static void sleep() {
        Thread.sleep(10);
    }
}
T.sleep();
System.out.println("ok");
```

- [ ] ok
- [x] 编译错误
- [ ] 抛出 InterruptedException
- [ ] 什么也不输出

解析：Thread.sleep 声明了 checked 异常 InterruptedException，sleep() 既没有 try-catch 也没有 throws，编译器报 unreported exception。

**代码题**：下面代码能编译吗？运行结果是什么？

```java
class T {
    static int parse(String s) {
        return Integer.parseInt(s);
    }
}
System.out.println(T.parse("12a"));
```

- [ ] 12
- [ ] 编译错误
- [x] 抛出 NumberFormatException
- [ ] 0

解析：NumberFormatException 是 unchecked 异常，不需要声明也能编译；运行时 "12a" 不是合法整数，抛出 NumberFormatException。

**判断题**：
- ✅ 编译器会强制处理 checked 异常 —— 必须 try-catch 或者在方法签名上 throws
- ❌ NullPointerException 是 checked 异常 —— 它继承 RuntimeException，是 unchecked

### 读懂异常栈（stack trace）

**概念**：程序抛出未处理的异常时，控制台会打印 stack trace：第一行是异常类型和原因，下面每一行是调用栈中的一个方法和行号

**一句话**：先看第一行知道是什么异常、为什么（比如 ArrayIndexOutOfBoundsException: 11），再从上往下找第一行属于自己代码的位置，那里通常就是出错点；越往下越接近程序入口 main；被包装过的异常还要看 Caused by。

**详细解释**：
PPT 的例子：
```java
Exception in thread "main" java.lang.ArrayIndexOutOfBoundsException: 11
    at D1_Exception.ExceptionDemo.method3(ExceptionDemo.java:32)
    at D1_Exception.ExceptionDemo.main(ExceptionDemo.java:9)
```
第一行：在 main 线程，发生了 ArrayIndexOutOfBoundsException，原因是下标 11。
第二行：出错的位置是 method3，第 32 行；第三行：是 main 第 9 行调用了 method3。
很长的栈（比如网络异常）里大部分是 JDK 内部调用，要找自己项目包名下的那几行。
代码里拿异常信息：e.getMessage() 只返回原因；e.toString() 返回"全类名: 原因"；e.printStackTrace() 打印完整的栈；e.getCause() 拿到包装的原始异常。

**问题**：程序报错时怎么读异常栈、快速定位问题？

**答案要点**：
1. 第一行：异常类型 + 原因（message）
2. 下面每行是调用栈：类、方法、文件名和行号
3. 越靠上越接近出错点，越靠下越接近 main
4. 找第一个属于自己代码的那一行
5. 有 Caused by 时，最底下的 Caused by 往往是根本原因

**常见陷阱**：
- ❌ 只看最后一行或者只看 JDK 内部的调用
- ✅ 从上往下找第一行自己代码的位置
- ❌ catch 之后什么都不做（吞掉异常）
- ✅ 至少记录日志或 e.printStackTrace()，否则问题无从排查

**追问**：
- Q: 重新抛出包装后的异常时，怎么保留原始异常栈？
- A: 把原始异常作为 cause 传进去：throw new ServiceException("msg", e)，栈里会出现 Caused by

**代码题**：下面代码依次输出什么？（多行用空格隔开）

```java
Exception e = new IllegalStateException("bad state");
System.out.println(e.getMessage());
System.out.println(e);
```

- [x] bad state java.lang.IllegalStateException: bad state
- [ ] bad state IllegalStateException
- [ ] java.lang.IllegalStateException: bad state bad state
- [ ] bad state bad state

解析：getMessage() 只返回创建异常时传入的原因；直接打印异常对象调用的是 toString()，格式是"全类名: message"。

**判断题**：
- ✅ 异常栈的第一行会显示异常的类型和原因 —— 比如 java.lang.ArrayIndexOutOfBoundsException: 11
- ❌ 异常栈里越往下的行越接近真正出错的位置 —— 越往上越接近出错点，越往下越接近 main
