# 异常处理

### try-catch 与 catch 的顺序

**概念**：可能抛异常的代码放在 try 里，catch 块处理 try 中抛出的异常；try 里一旦发生异常，执行立刻停止，跳到第一个匹配的 catch

**一句话**：一个 try 可以跟多个 catch，但只有第一个匹配的会执行，所以子类异常的 catch 要写在父类前面，最通用的 catch (Exception e) 放最后，顺序写反会编译错误；Java 7 起支持 multi-catch：catch (A | B e)；try-catch 也可以嵌套。

**详细解释**：
try-catch 可以放在任何你觉得会抛异常的方法里。
If an exception occurs in the try block, execution stops at that point, and control is immediately transferred to the matching catch block。
Order of catch is important：catch having super class types should be defined later than the catch clauses with subclass types；most general handling must come last。
PPT 的例子：
```java
try {
    // risky code
} catch (IOException e) {
    System.out.println("File error: " + e.getMessage());
} catch (ArithmeticException e) {
    System.out.println("Math error: " + e.getMessage());
} catch (Exception e) {
    System.out.println("General error: " + e.getMessage());
}
```
multi-catch：catch (Exception1 | Exception2 | Exception3 e) {...}，| 连接的异常之间不能有父子关系，e 隐式是 final。

**问题**：多个 catch 块的执行规则是什么？顺序有什么要求？

**答案要点**：
1. try 中发生异常后，后面的语句不再执行，跳到匹配的 catch
2. 多个 catch 只执行第一个匹配的
3. 子类异常写在前面，父类异常写在后面，否则编译错误
4. Java 7 起支持 multi-catch，用 | 分隔，类型之间不能有继承关系
5. try-catch 可以嵌套

**常见陷阱**：
- ❌ 把 catch (Exception e) 写在最前面
- ✅ 后面的 catch 永远到不了，编译器报 "exception has already been caught"
- ❌ 以为匹配的多个 catch 会依次都执行
- ✅ 只执行第一个匹配的 catch

**追问**：
- Q: catch 一个 try 里根本不可能抛出的 checked 异常会怎样？
- A: 编译错误（exception is never thrown in body of corresponding try statement）；但 catch Exception 或 unchecked 异常没有这个限制

**代码题**：下面代码输出什么？

```java
try {
    String s = null;
    System.out.print("A ");
    s.length();
    System.out.print("B ");
} catch (IllegalArgumentException e) {
    System.out.print("C ");
} catch (RuntimeException e) {
    System.out.print("D ");
} catch (Exception e) {
    System.out.print("E ");
}
System.out.println("F");
```

- [x] A D F
- [ ] A B F
- [ ] A D E F
- [ ] A C D E F

解析：s.length() 抛出 NullPointerException，B 不会执行；NullPointerException 不是 IllegalArgumentException，跳过 C；它是 RuntimeException，匹配 D 后就不再看后面的 catch；最后继续执行 F。

**代码题**：下面代码能编译吗？

```java
try {
    int x = 10 / 0;
} catch (Exception e) {
    System.out.println("general");
} catch (ArithmeticException e) {
    System.out.println("math");
}
```

- [ ] general
- [ ] math
- [x] 编译错误
- [ ] general math

解析：ArithmeticException 是 Exception 的子类，写在 catch (Exception e) 后面永远不会被执行到，编译器报错。父类异常必须放在后面。

**判断题**：
- ✅ 一个 try 后面的多个 catch 中，最多只有一个会执行 —— 只执行第一个匹配的 catch
- ❌ multi-catch 可以写 catch (IOException | Exception e) —— 用 | 连接的类型不能有父子关系，否则编译错误

### finally 与 try-with-resources

**概念**：finally 块写在 try 或 try-catch 之后，里面的代码无论是否发生异常、即使 try 里 return 了，都会执行；try-with-resources 是自动关闭资源的另一种写法

**一句话**：finally 常用来释放资源（关文件、关数据库连接）；try 里 return 时会先执行 finally 再返回，返回值在 finally 执行前就已经确定，但如果 finally 自己 return，会覆盖 try 的返回值；只有 System.exit 或 JVM 崩溃时 finally 才不执行；Java 7 的 try-with-resources 会自动按相反顺序关闭实现了 AutoCloseable 的资源。

**详细解释**：
It executes in all circumstances, whether: an exception occurs / no exception occurs / a method returns using return。
Typical use cases：When we need to release some resources (open a file, start a database connection, etc.) in the try block；An alternative way is using try-with-resources statement。
```java
try (BufferedReader br = new BufferedReader(new FileReader("in.txt"))) {
    System.out.println(br.readLine());
}   // 自动调用 br.close()，即使抛了异常
```
try-with-resources 的规则：资源要实现 AutoCloseable；多个资源用分号隔开，关闭顺序和打开顺序相反；try 块和 close 都抛异常时，close 的异常作为 suppressed 附在主异常上。
try { return x; } finally { x = 2; }：返回值在执行 finally 之前已经保存，修改基本类型变量不影响返回值。

**问题**：finally 一定会执行吗？try 里 return 了 finally 还执行吗？

**答案要点**：
1. 有异常、无异常、try 里 return，finally 都会执行
2. try 里 return 时，先保存返回值，再执行 finally，最后返回
3. finally 里写 return 会覆盖 try 的返回值（不推荐）
4. System.exit()、JVM 崩溃、线程被杀时 finally 不执行
5. 释放资源优先用 try-with-resources，自动按相反顺序关闭

**常见陷阱**：
- ❌ 在 finally 里写 return
- ✅ 会覆盖 try 的返回值，还会吞掉 try 里抛出的异常
- ❌ 以为在 finally 里修改返回的局部变量会改变返回结果
- ✅ 对基本类型无效，返回值在执行 finally 之前已经确定

**追问**：
- Q: try-with-resources 里的资源需要满足什么条件？
- A: 实现 AutoCloseable（或 Closeable）接口；Java 9 起还可以直接写已经声明好的 effectively final 变量

**代码题**：下面代码输出什么？

```java
class T {
    static int f() {
        try {
            return 1;
        } finally {
            System.out.print("finally ");
        }
    }
}
System.out.println(T.f());
```

- [x] finally 1
- [ ] 1 finally
- [ ] 1
- [ ] finally

解析：try 里 return 1 时，先把返回值 1 保存下来，再执行 finally 打印 "finally "，最后才真正返回 1，由 println 打印。

**代码题**：下面代码输出什么？

```java
class T {
    static int f() {
        int x = 1;
        try {
            return x;
        } finally {
            x = 2;
        }
    }
    static int g() {
        try {
            return 1;
        } finally {
            return 2;
        }
    }
}
System.out.println(T.f() + " " + T.g());
```

- [x] 1 2
- [ ] 2 2
- [ ] 1 1
- [ ] 2 1

解析：f 的返回值 1 在 finally 执行前已经确定，finally 里改 x 不影响结果；g 的 finally 里有 return 2，覆盖了 try 的 return 1。

**代码题**：下面代码输出什么？

```java
class Res implements AutoCloseable {
    String name;
    Res(String name) { this.name = name; System.out.print("open " + name + " "); }
    public void close() { System.out.print("close " + name + " "); }
}
try (Res a = new Res("A"); Res b = new Res("B")) {
    System.out.print("body ");
}
System.out.println();
```

- [x] open A open B body close B close A
- [ ] open A open B body close A close B
- [ ] open A open B body
- [ ] open A body close A open B close B

解析：try-with-resources 按声明顺序打开资源，执行完 try 块后按相反顺序自动调用 close()。

**判断题**：
- ✅ try 块中执行了 return，finally 块仍然会执行 —— finally 在方法真正返回之前执行
- ❌ 调用 System.exit(0) 之后，finally 块仍然会执行 —— System.exit 直接终止 JVM，finally 不会执行

### throw 与 throws

**概念**：throw 在方法体里主动抛出一个异常对象；throws 写在方法签名上，声明这个方法可能抛出的异常类型，让调用者知道并处理

**一句话**：throw 后面跟一个 Throwable 实例，比如 throw new IllegalArgumentException("age < 0")；throws 后面跟一个或多个异常类型；调用声明了 checked 异常的方法时，调用者要么 try-catch，要么自己也 throws 往上传；一直传到 main 都没处理，就交给默认异常处理器打印栈并终止程序；不要 throw 或 catch Error。

**详细解释**：
Throw：Used to explicitly throw an exception；"Something is going wrong"；Syntax: throw ThrowableInstance，例如 throw new InvalidCredentialException();
Throws：Added to the method signature to let the caller know about what exception the called method (callee) can throw；It is the responsibility of the caller to either handle the exception (try...catch) or pass the exception (throws clause)；If all the methods in a program pass the exception to their callers (including main()), then ultimately the exception passes to the default exception handler。
Throwing and catching errors are doable, but strongly discouraged。
重写方法时，子类方法 throws 的 checked 异常不能比父类更宽（可以更少、更具体，或者不抛）。

**问题**：throw 和 throws 有什么区别？

**答案要点**：
1. throw 用在方法体里，抛出一个异常对象
2. throws 用在方法签名上，声明可能抛出的异常类型
3. throw 一次只能抛一个，throws 可以声明多个
4. 调用者对 checked 异常要么 try-catch，要么继续 throws
5. 一直传到 main 也没处理，由默认处理器打印栈并终止程序

**对比**：
| | throw | throws |
|---|---|---|
| 位置 | 方法体内 | 方法签名上 |
| 后面跟 | 一个异常对象 | 一个或多个异常类型 |
| 作用 | 真正抛出异常 | 声明可能抛出的异常 |
| 例子 | throw new IOException("disk") | void read() throws IOException |

**常见陷阱**：
- ❌ 抛出 checked 异常却不在方法上声明 throws
- ✅ 编译错误 unreported exception；unchecked 异常才可以不声明
- ❌ 写成 throw IllegalArgumentException;
- ✅ throw 后面必须是异常对象：throw new IllegalArgumentException(...)

**追问**：
- Q: 子类重写父类方法时，throws 有什么限制？
- A: 不能抛出比父类方法更宽的 checked 异常，可以不抛、少抛或抛更具体的子类异常；unchecked 异常不受限制

**代码题**：下面代码能编译吗？

```java
class T {
    static void read() {
        throw new IOException("disk");
    }
}
T.read();
```

- [ ] 抛出 IOException
- [x] 编译错误
- [ ] 什么也不输出
- [ ] disk

解析：IOException 是 checked 异常，read() 抛出了它却没有 try-catch，也没有在签名上 throws IOException，编译器报 unreported exception。

**代码题**：下面代码输出什么？

```java
class T {
    static void check(int age) {
        if (age < 0) throw new IllegalArgumentException("age < 0");
        System.out.print("valid ");
    }
}
try {
    T.check(5);
    T.check(-1);
} catch (IllegalArgumentException e) {
    System.out.print("caught: " + e.getMessage());
}
System.out.println();
```

- [x] valid caught: age < 0
- [ ] valid valid caught: age < 0
- [ ] caught: age < 0
- [ ] 编译错误

解析：IllegalArgumentException 是 unchecked 异常，不用声明 throws；check(5) 正常打印 valid，check(-1) 用 throw 主动抛出异常，被外层 catch 捕获。

**判断题**：
- ✅ throws 后面可以声明多个异常类型 —— 比如 throws IOException, SQLException
- ❌ throw 后面跟的是异常类型名 —— throw 后面必须是一个异常对象（实例）

### 异常传播

**概念**：异常传播（Exception Propagation）指一个方法没有处理的异常，会沿着调用栈传给调用它的方法，直到被处理或到达 main

**一句话**：异常发生时，JVM 先在当前方法找匹配的 catch，找不到就把异常抛给调用方，一层层往上，直到某层处理了它；如果一直到 main 都没处理，JVM 终止程序并打印异常栈；checked 异常沿途每个方法都要用 throws 声明，unchecked 异常自动传播。

**详细解释**：
What is Exception Propagation：how an exception is passed from one method to another in the call stack；If a method does not handle an exception, it is propagated to the calling method。
How does propagation work：
1. JVM searches for a matching catch block in the current method
2. If no catch block is found, the exception is propagated to the calling method
3. This process continues until the exception is handled or reach the main() method
4. If unhandled, the JVM terminates the program and prints the stack trace
Key points：Checked exceptions must be explicitly declared using throws and handled by the caller；Unchecked exceptions are propagated automatically without requiring declaration。
异常传播时，沿途每个方法中异常发生点之后的代码都不会执行（finally 除外）。

**问题**：什么是异常传播？异常没有被处理时会发生什么？

**答案要点**：
1. 当前方法没有处理的异常会传给调用方
2. 沿调用栈一层层往上找匹配的 catch
3. 被某一层处理后，程序从那层的 catch 之后继续执行
4. 一直到 main 都没处理：JVM 终止程序并打印异常栈
5. checked 异常沿途要 throws 声明，unchecked 自动传播

**常见陷阱**：
- ❌ 以为异常被外层捕获后，内层方法里异常之后的代码还会执行
- ✅ 异常点之后的代码都被跳过，只有 finally 会执行

**追问**：
- Q: 多线程里，子线程抛出未处理的异常会传播到主线程吗？
- A: 不会，异常只在当前线程的调用栈里传播；子线程会终止，可以用 UncaughtExceptionHandler 处理

**代码题**：下面代码输出什么？

```java
class T {
    static void a() {
        System.out.print("a1 ");
        b();
        System.out.print("a2 ");
    }
    static void b() {
        System.out.print("b1 ");
        int x = 1 / 0;
        System.out.print("b2 ");
    }
}
try {
    T.a();
} catch (ArithmeticException e) {
    System.out.print("caught ");
}
System.out.println("end");
```

- [x] a1 b1 caught end
- [ ] a1 b1 b2 a2 caught end
- [ ] a1 b1 a2 caught end
- [ ] a1 b1 caught

解析：b() 里除以 0 抛出 ArithmeticException，b 没有处理，传给 a；a 也没处理，传给调用处被 catch 捕获。b2、a2 都被跳过，catch 之后程序继续打印 end。

**判断题**：
- ✅ 未处理的异常会沿着调用栈传给调用方 —— 直到被 catch 或到达 main
- ❌ unchecked 异常必须用 throws 声明才能向上传播 —— unchecked 异常自动传播，不需要声明

### 自定义异常

**概念**：自定义异常是继承 Exception 或 RuntimeException 的类，按需提供构造器，在需要时用 throw 抛出

**一句话**：想让调用方必须处理就继承 Exception（checked），表示程序错误或不想强制处理就继承 RuntimeException（unchecked）；通常提供带 message 的构造器，以及带 message 和 cause 的构造器，方便保留原始异常；自定义异常让错误含义更清晰，比如 InsufficientFundsException、InvalidCredentialException。

**详细解释**：
A class which is a subclass of Exception (or RuntimeException)；Provide constructor as needed；Use throw keyword to throw exception whenever you want to raise the exception；Can be either checked or unchecked exception：Extend Exception class if you want to create checked exception；Extend RuntimeException class if you want to create unchecked exception。
```java
public class InsufficientFundsException extends Exception {
    public InsufficientFundsException(String message) { super(message); }
    public InsufficientFundsException(String message, Throwable cause) { super(message, cause); }
}
```
命名习惯以 Exception 结尾；业务项目常定义一个基础异常（比如 BusinessException extends RuntimeException），再按错误码细分。

**问题**：怎么自定义异常？什么时候继承 Exception、什么时候继承 RuntimeException？

**答案要点**：
1. 继承 Exception 或 RuntimeException
2. 提供需要的构造器，通常调用 super(message) / super(message, cause)
3. 继承 Exception 是 checked，调用方必须处理
4. 继承 RuntimeException 是 unchecked，不强制处理
5. 用 throw new XxxException(...) 抛出，名字以 Exception 结尾

**常见陷阱**：
- ❌ 自定义异常不传 message，也不保留 cause
- ✅ 至少传 message；包装别的异常时传入 cause，排查时才能看到根因

**追问**：
- Q: 业务代码里自定义异常更常继承哪个？
- A: 多数项目继承 RuntimeException，避免每层方法都写 throws，再由全局异常处理器统一转成错误响应

**代码题**：下面代码输出什么？

```java
class InsufficientFundsException extends Exception {
    InsufficientFundsException(String msg) { super(msg); }
}
class Account {
    int balance = 50;
    void withdraw(int amount) throws InsufficientFundsException {
        if (amount > balance) throw new InsufficientFundsException("need " + (amount - balance) + " more");
        balance -= amount;
    }
}
Account acc = new Account();
try {
    acc.withdraw(80);
} catch (InsufficientFundsException e) {
    System.out.println(e.getMessage() + " " + acc.balance);
}
```

- [x] need 30 more 50
- [ ] need 30 more -30
- [ ] need 80 more 50
- [ ] 编译错误

解析：取 80 超过余额 50，抛出自定义的 checked 异常，throw 之后的 balance -= amount 不会执行，所以余额仍是 50。

**代码题**：下面代码能编译吗？

```java
class InvalidAgeException extends Exception {
    InvalidAgeException(String msg) { super(msg); }
}
class T {
    static void check(int age) {
        if (age < 0) throw new InvalidAgeException("negative");
    }
}
T.check(-1);
```

- [ ] 抛出 InvalidAgeException
- [x] 编译错误
- [ ] 什么也不输出
- [ ] negative

解析：InvalidAgeException 继承 Exception，是 checked 异常；check 抛出它却没有声明 throws，编译报错。改成继承 RuntimeException 就可以不声明。

**判断题**：
- ✅ 继承 RuntimeException 的自定义异常不需要在方法上声明 throws —— 它是 unchecked 异常
- ❌ 自定义异常必须继承 Throwable 并实现所有方法 —— 一般继承 Exception 或 RuntimeException，只需要提供构造器
