# 排序

### Collections.sort 与 Arrays.sort

**概念**：Java 可以手写排序算法（冒泡、插入、快排、归并），也可以用内置工具：List 用 Collections.sort(list)，数组用 Arrays.sort(array)

**一句话**：Collections.sort 内部用 TimSort（归并排序 + 插入排序），是稳定排序；Arrays.sort 对对象数组也用 TimSort，对基本类型数组用双轴快排；元素要么实现 Comparable（自然顺序），要么额外传一个 Comparator。

**详细解释**：
手写算法：Bubble sort、Insertion sort、Quick sort、Merge sort。
内置工具：For List<E> → Collections.sort(list)，内部是 TimSort：merge sort + insertion sort；For Array → Arrays.sort(array)。
TimSort 利用数据中已经有序的片段（run），小片段用插入排序，再归并；最好 O(n)，最坏 O(n log n)，稳定。
稳定排序：相等的元素排序后保持原来的相对顺序，按多个条件依次排序时很重要。
Java 8 起 List 自己也有 sort(Comparator) 方法，Collections.sort 内部就是调用它。

**问题**：Java 里怎么给集合和数组排序？Collections.sort 用的是什么算法？

**答案要点**：
1. List 用 Collections.sort(list) 或 list.sort(comparator)
2. 数组用 Arrays.sort(array)
3. Collections.sort 用 TimSort（归并 + 插入），稳定，O(n log n)
4. Arrays.sort 对基本类型用双轴快排，对对象用 TimSort
5. 元素要实现 Comparable，或者传入 Comparator

**常见陷阱**：
- ❌ 认为 Arrays.sort(int[]) 也是稳定的 TimSort
- ✅ 基本类型数组用双轴快排；基本类型不存在"相等元素的相对顺序"问题，所以不需要稳定
- ❌ 对没有实现 Comparable 的对象直接调用 Collections.sort(list)
- ✅ 编译不过（泛型要求 T extends Comparable），要传入 Comparator

**追问**：
- Q: 为什么对象排序要用稳定排序？
- A: 对象相等时可能其他字段不同，比如先按名字排、再按年龄稳定排序，名字相同的人仍保持年龄顺序

**代码题**：下面代码输出什么？

```java
List<String> list = new ArrayList<>(List.of("pear", "apple", "fig"));
Collections.sort(list);
int[] arr = {3, 1, 2};
Arrays.sort(arr);
System.out.println(list + " " + Arrays.toString(arr));
```

- [x] [apple, fig, pear] [1, 2, 3]
- [ ] [fig, pear, apple] [1, 2, 3]
- [ ] [pear, apple, fig] [3, 1, 2]
- [ ] [apple, fig, pear] [3, 2, 1]

解析：String 的自然顺序是字典序，数字是升序。

**代码题**：下面代码输出什么？

```java
List<String> list = new ArrayList<>(List.of("bb", "a", "cc", "d"));
list.sort(Comparator.comparingInt(String::length));
System.out.println(list);
```

- [x] [a, d, bb, cc]
- [ ] [d, a, cc, bb]
- [ ] [a, d, cc, bb]
- [ ] [bb, cc, a, d]

解析：按长度排序；TimSort 是稳定的，长度相同的元素保持原来的相对顺序：a 在 d 前，bb 在 cc 前。

**判断题**：
- ✅ Collections.sort 是稳定排序 —— 内部用 TimSort，相等元素保持原有顺序
- ❌ Arrays.sort 对 int[] 用的也是 TimSort —— 基本类型数组用双轴快排（Dual-Pivot Quicksort）

### Comparable 与 Comparator

**概念**：Comparable<T> 定义对象的自然顺序，由类自己实现 compareTo；Comparator<T> 定义自定义顺序，独立于类，可以为同一类型写多种排序方式

**一句话**：String 按字典序、数字按大小、日期按先后，这些都是通过实现 Comparable 定义的自然顺序，Collections.sort、Arrays.sort、TreeSet、TreeMap 都会用它；需要别的排序方式、或者不能修改类的源码时，就写一个 Comparator 传进去。

**详细解释**：
Natural Ordering：很多核心类实现了 Comparable<T>：String → 字典序（Lexicographical）；Number 及其子类 → 数值升序；Date / LocalDate → 时间先后（Chronological）。
Comparable：类自己 implements Comparable<T>，重写 int compareTo(T o)。
Comparator：单独的类（或 lambda）implements Comparator<T>，重写 int compare(T o1, T o2)。
课件的例子：Movie implements Comparable<Movie>，compareTo 按 year 升序（自然顺序）；RatingCompare 按 rating 排；NameCompare 按 name 排。
用法：Collections.sort(movies) 按自然顺序；Collections.sort(movies, new RatingCompare()) 按评分。
TreeSet / TreeMap 里的元素（key）没有自然顺序、又没传 Comparator 时，插入会抛 ClassCastException。

**问题**：Comparable 和 Comparator 有什么区别？分别什么时候用？

**答案要点**：
1. Comparable 定义自然顺序，类自己实现 compareTo(T o)
2. Comparator 定义自定义顺序，在类外实现 compare(T o1, T o2)
3. 一个类只有一种自然顺序，但可以有任意多个 Comparator
4. Comparable 在 java.lang，Comparator 在 java.util
5. 不能修改类源码、或需要多种排序时用 Comparator

**对比**：
| | Comparable | Comparator |
|---|---|---|
| 包 | java.lang | java.util |
| 方法 | int compareTo(T o) | int compare(T o1, T o2) |
| 写在哪 | 类自己实现 | 类外单独实现 / lambda |
| 几种顺序 | 一种（自然顺序） | 任意多种 |
| 使用 | Collections.sort(list) | Collections.sort(list, cmp) |

**常见陷阱**：
- ❌ 以为实现 Comparable 要重写 compare(a, b)
- ✅ Comparable 是 compareTo(o)，Comparator 才是 compare(o1, o2)
- ❌ 把没有实现 Comparable 的对象放进 TreeSet 又不传 Comparator
- ✅ 运行时抛 ClassCastException

**追问**：
- Q: compareTo 和 equals 需要保持一致吗？
- A: 强烈建议一致（compareTo 为 0 时 equals 为 true）；否则 TreeSet 和 HashSet 对"重复"的判断会不同

**代码题**：下面代码依次输出什么？（多行用空格隔开）

```java
class Movie implements Comparable<Movie> {
    String name; double rating; int year;
    Movie(String name, double rating, int year) { this.name = name; this.rating = rating; this.year = year; }
    public int compareTo(Movie other) { return this.year - other.year; }
    public String toString() { return name; }
}
List<Movie> list = new ArrayList<>(List.of(new Movie("B", 9.0, 2010), new Movie("A", 7.5, 1999), new Movie("C", 8.0, 2020)));
Collections.sort(list);
System.out.println(list);
list.sort((m1, m2) -> Double.compare(m1.rating, m2.rating));
System.out.println(list);
```

- [x] [A, B, C] [A, C, B]
- [ ] [B, A, C] [A, C, B]
- [ ] [A, B, C] [B, C, A]
- [ ] [C, B, A] [A, C, B]

解析：Collections.sort(list) 用 Movie 的自然顺序（按 year 升序）：1999 A、2010 B、2020 C；再传入按 rating 比较的 Comparator：7.5 A、8.0 C、9.0 B。

**代码题**：下面代码运行结果是什么？

```java
class Box {
    int size;
    Box(int size) { this.size = size; }
}
Set<Box> set = new TreeSet<>();
set.add(new Box(1));
System.out.println(set.size());
```

- [ ] 1
- [ ] 0
- [x] 抛出 ClassCastException
- [ ] 编译错误

解析：TreeSet 要比较元素来排序；Box 既没有实现 Comparable，也没有传 Comparator，add 时尝试把它转成 Comparable，抛 ClassCastException。

**判断题**：
- ✅ 同一个类可以有多个 Comparator，实现不同的排序方式 —— Comparator 独立于类定义
- ❌ 实现 Comparable 接口需要重写 compare(T o1, T o2) 方法 —— Comparable 的方法是 compareTo(T o)

### compare 的返回值约定

**概念**：重写 compare(o1, o2) 或 compareTo(o2) 时，返回负数表示 o1 排在前面，返回 0 表示顺序相等，返回正数表示 o1 排在后面

**一句话**：返回值只看正负号：< 0 → o1 在前，== 0 → 相等，> 0 → o1 在后；`this.year - other.year` 就是升序，反过来减是降序；用减法比较可能整数溢出，推荐用 Integer.compare；TreeSet / TreeMap 把比较结果为 0 的两个元素当成重复。

**详细解释**：
Contract：< 0 → if o1 comes before o2；== 0 → if o1 is equal to o2 in order；> 0 → if o1 comes after o2。
课件的写法：`return this.year - other.year;`（按 year 升序）。
溢出问题：当数值范围很大或有负数时，a - b 可能溢出，符号就反了，比如 Integer.MIN_VALUE - 1 会变成一个很大的正数。安全写法：Integer.compare(a, b)、Double.compare(a, b)。
降序：Comparator.reverseOrder()、cmp.reversed()，或者交换参数 Integer.compare(b, a)。
TreeSet / TreeMap 不用 equals 判断重复，而是看 compare 是否返回 0，所以一个"按长度比较"的 Comparator 会让长度相同的字符串只保留一个。

**问题**：compare / compareTo 的返回值代表什么？实现时要注意什么？

**答案要点**：
1. 负数：o1 在 o2 前面；0：顺序相等；正数：o1 在 o2 后面
2. 只看符号，不看具体大小
3. 用减法实现可能溢出，用 Integer.compare / Double.compare
4. 降序可以用 reversed() 或交换参数
5. TreeSet / TreeMap 把比较结果为 0 的元素视为重复

**常见陷阱**：
- ❌ 用 a - b 比较任意范围的 int
- ✅ 用 Integer.compare(a, b)，不会溢出
- ❌ 以为 TreeSet 用 equals 去重
- ✅ TreeSet 用 compare / compareTo 的结果去重，结果为 0 就当成同一个元素

**追问**：
- Q: compare 的返回值必须是 -1、0、1 吗？
- A: 不必，只看正负号；但调用方也只能判断符号，不能写成 compare(...) == -1

**代码题**：下面代码输出什么？

```java
Integer[] arr = {Integer.MIN_VALUE, 1};
Arrays.sort(arr, (a, b) -> a - b);
System.out.println(Arrays.toString(arr));
```

- [x] [1, -2147483648]
- [ ] [-2147483648, 1]
- [ ] 抛出 ArithmeticException
- [ ] [1, 1]

解析：比较 1 和 MIN_VALUE 时，1 - Integer.MIN_VALUE 溢出成了负数，排序认为 1 更小，结果顺序反了；用 Integer.compare(a, b) 才能得到正确的 [-2147483648, 1]。

**代码题**：下面代码输出什么？

```java
Set<String> set = new TreeSet<>((a, b) -> a.length() - b.length());
set.add("cat");
set.add("dog");
set.add("horse");
System.out.println(set);
```

- [x] [cat, horse]
- [ ] [cat, dog, horse]
- [ ] [dog, cat, horse]
- [ ] [horse, cat]

解析：TreeSet 用 Comparator 判断重复："dog" 和 "cat" 长度相同，compare 返回 0，被当成重复元素没有加进去。

**判断题**：
- ✅ compare(o1, o2) 返回负数表示 o1 排在 o2 前面 —— 这是 Comparator 的返回值约定
- ❌ TreeSet 用 equals 判断元素是否重复 —— TreeSet 用 compareTo / compare 是否返回 0 来判断
