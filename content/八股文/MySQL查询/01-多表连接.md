# 多表连接

### JOIN 的作用与 INNER JOIN

**概念**：JOIN 按某个匹配的列把两张或多张表的行组合在一起；INNER JOIN 只返回两张表里都能匹配上的行，任何一边没有匹配的行都不会出现在结果里

**一句话**：JOIN 用匹配列的值把行配对，匹配列不需要同名、也不需要是主键或外键；INNER JOIN（INNER 可以省略）只保留两边都匹配的行；一对多连接时"一"那边的行会被重复，再做 SUM 容易重复计算；NATURAL JOIN 自动按所有同名列连接，同名但含义不同的列会被误当成连接条件。

**详细解释**：
A JOIN clause is used to combine rows from 2 or more tables, based on a matching column；Matching Columns DO NOT have to have the same name；Matching Columns DO NOT need to be keys；Scope: table to table, table to view。
例子：Customer(id, name)、Order(orderno, name, customer_id)，按 Customer.id = Order.customer_id 找某个客户的订单。
Inner Join returns records that have matching values in both tables；If there are records in one table that do not have matches in the other table these records will not be shown。
语法：T1 INNER JOIN T2 ON <condition>；T1 JOIN T2 ON <condition>；T1 NATURAL JOIN T2。
课件例子：STUDENT(NETID, NAME)、ENROLL(NETID, CRN)、COURSE(CRN, NAME)，查每个学生选了哪些课（课件把第三张表又写成了 STUDENT(NETID, NAME)，应为 COURSE(CRN, NAME)）：
```sql
SELECT s.NAME, c.NAME
FROM STUDENT s
JOIN ENROLL e ON s.NETID = e.NETID
JOIN COURSE c ON e.CRN = c.CRN;
```
没选课的 Betty、Risa 和没人选的 COMP 533 都不出现；Andre 选了两门，出现两行。
多表连接时每多一个 JOIN 就多一个 ON；忘写 ON 条件会得到笛卡尔积。

**问题**：什么是 JOIN？INNER JOIN 返回哪些行？

**答案要点**：
1. JOIN 按匹配列把多张表的行组合起来，匹配列不必同名，也不必是键
2. INNER JOIN 只返回两边都能匹配的行，没有匹配的行被排除
3. JOIN 和 INNER JOIN 是同一个意思
4. 一对多连接会让"一"那边的行重复出现，聚合时要注意重复计算
5. NATURAL JOIN 按所有同名列连接，容易误连，一般显式写 ON

**对比**：
| 写法 | 连接条件 | 注意 |
|---|---|---|
| A JOIN B ON A.x = B.y | 显式指定 | 推荐 |
| A NATURAL JOIN B | 所有同名列自动等值连接 | 多出同名列时结果会变 |
| FROM A, B WHERE A.x = B.y | 写在 WHERE 里 | 旧写法，忘写 WHERE 就成了笛卡尔积 |

**常见陷阱**：
- ❌ 用 NATURAL JOIN 连 STUDENT、ENROLL、COURSE，以为会按 NETID 和 CRN 连接
- ✅ STUDENT 和 COURSE 都有 NAME 列，NAME 也会被当成连接条件，结果一行都没有
- ❌ 订单表和付款表都按客户连接后再分别 SUM 金额
- ✅ 两个"多"的表连在一起会把行数相乘，SUM 被放大，应该先分别聚合再连接

**追问**：
- Q: JOIN 的连接列一定要建外键吗？
- A: 不需要，JOIN 只看值是否匹配；外键是保证数据正确的约束，和能不能 JOIN 无关，不过连接列上最好有索引

### CROSS JOIN 与笛卡尔积

**概念**：CROSS JOIN 返回两张表所有行的两两组合，也就是笛卡尔积：A × B = {(a, b) | a ∈ A and b ∈ B}

**一句话**：CROSS JOIN 不需要连接条件，结果行数等于两张表行数的乘积，数据量大而且通常不是想要的结果；FROM A, B 不写 WHERE 也是笛卡尔积；只要有一张表是空的，结果就是 0 行。

**详细解释**：
Cross Join：Display every possible combination of all values in the designated columns；Cartesian Product；A lot of data, usually not intended。
语法：T1 CROSS JOIN T2。
课件例子：A = {x, y, z}，B = {1, 2, 3}，A × B 有 9 个组合；STUDENT 4 行 CROSS JOIN ENROLL 3 行得到 12 行，每个学生都和每条选课记录配了一次，不管 NETID 是否相同。
INNER JOIN 可以理解成"先做笛卡尔积，再用 ON 条件筛选"（数据库实际不会这样执行）。
有意义的用法：生成所有组合，比如所有尺码 × 所有颜色、每个员工 × 每一天的排班表。

**问题**：什么是 CROSS JOIN？结果有多少行？

**答案要点**：
1. CROSS JOIN 就是笛卡尔积，每一行和另一张表的每一行组合
2. 不需要连接条件
3. 结果行数 = m × n，有一张表为空则结果为 0 行
4. FROM A, B 不写 WHERE 条件也是笛卡尔积
5. 多表 JOIN 漏写 ON 条件会意外得到笛卡尔积，结果行数暴涨

**常见陷阱**：
- ❌ 写 FROM orders, customers 却忘了 WHERE 连接条件
- ✅ 得到 订单数 × 客户数 行，既慢又错
- ❌ 以为 CROSS JOIN 一张空表会原样返回另一张表
- ✅ m × 0 = 0，结果是空的；想保留另一张表的行要用 LEFT JOIN

**追问**：
- Q: CROSS JOIN 有什么实际用途？
- A: 生成全部组合，比如尺码表 × 颜色表得到所有商品规格，或者员工表 × 日期表生成排班模板，再 LEFT JOIN 实际数据找出缺失的组合

- ✅ 两张表分别有 m 行和 n 行，CROSS JOIN 的结果有 m × n 行 —— 笛卡尔积是所有行的两两组合
- ❌ CROSS JOIN 必须用 ON 指定连接条件 —— CROSS JOIN 不需要连接条件，每一行都和另一张表的每一行组合

### LEFT JOIN 与 RIGHT JOIN

**概念**：LEFT JOIN 返回左表的所有行，以及右表中匹配的行，右表没有匹配时这些列填 NULL；RIGHT JOIN 反过来保留右表的所有行

**一句话**：LEFT JOIN 保留左表全部行，右边没匹配上的填 NULL；A RIGHT JOIN B 等价于 B LEFT JOIN A，团队里最好统一用一个方向；右表的过滤条件写在 ON 里，左表仍然全部保留，写在 WHERE 里会把 NULL 行过滤掉，LEFT JOIN 就退化成了 INNER JOIN；LEFT JOIN 之后计数要用 COUNT(右表的列)，COUNT(*) 会把没匹配的那一行也算成 1。

**详细解释**：
The LEFT JOIN keyword returns all records from the left table and the matching records from the right table；If there is no matching record, NULL will be assigned in the result set；It's a good idea to choose one direction (either LEFT or RIGHT) and use it to maintain consistency。
```sql
SELECT column_name(s)
FROM left_table
LEFT JOIN right_table
ON left_table.column_name = right_table.column_name;
```
课件例子（Query all students and show the enrollment process）：STUDENT s LEFT JOIN ENROLL e ON s.NETID = e.NETID 得到 5 行：abc1 Andre abc1 123；abc1 Andre abc1 345；bcd2 Betty NULL NULL；cde4 Chris cde4 123；rbm2 Risa NULL NULL。
课件例子（Query all the enrollment status in course）：ENROLL e RIGHT JOIN COURSE c ON e.CRN = c.CRN 得到 4 行，没人选的 234 COMP 533 那一行 NETID、CRN 是 NULL。
（课件 LEFT JOIN 那一页中间那张 12 行的表其实是 CROSS JOIN 的结果，右边的 RIGHT JOIN 查询属于下一页。）
ON 和 WHERE 的区别：ON 决定"怎么配对"，配不上的左表行仍然保留；WHERE 在连接之后过滤整行，右表列为 NULL 的行会被 e.crn = 123 这样的条件过滤掉。
LEFT OUTER JOIN 和 LEFT JOIN 是同一个意思，OUTER 可以省略。

**问题**：LEFT JOIN 和 INNER JOIN 有什么区别？右表的过滤条件写在 ON 里和 WHERE 里有什么不同？

**答案要点**：
1. LEFT JOIN 保留左表所有行，右表没匹配的列填 NULL；INNER JOIN 只保留匹配的行
2. A RIGHT JOIN B 等价于 B LEFT JOIN A，最好统一用一个方向
3. 右表条件写在 ON 里：只影响配对，左表行全部保留
4. 右表条件写在 WHERE 里：NULL 行被过滤，效果等于 INNER JOIN
5. LEFT JOIN 后统计数量用 COUNT(右表列)，不能用 COUNT(*)

**对比**：
| 写法 | 左表没匹配的行 | 效果 |
|---|---|---|
| LEFT JOIN e ON s.id = e.sid AND e.crn = 123 | 保留，右边是 NULL | 所有学生 + 是否选了 123 |
| LEFT JOIN e ON s.id = e.sid WHERE e.crn = 123 | 被过滤 | 只剩选了 123 的学生 |
| INNER JOIN e ON s.id = e.sid AND e.crn = 123 | 不保留 | 只剩选了 123 的学生 |

**常见陷阱**：
- ❌ 想列出所有学生和他们 123 课程的成绩，把 e.crn = 123 写在 WHERE 里
- ✅ 没选 123 的学生被过滤掉了，条件要写在 ON 里
- ❌ LEFT JOIN 后用 COUNT(*) 统计每个学生选了几门课
- ✅ 没选课的学生也有一行（右边是 NULL），COUNT(*) 得 1，要用 COUNT(e.crn) 得 0

**追问**：
- Q: 为什么建议只用 LEFT JOIN，不用 RIGHT JOIN？
- A: 两者可以互相改写，统一用 LEFT JOIN 时"主表"总是写在最前面，多表连接时更容易读懂哪张表的行会全部保留

### 反连接：查找没有匹配的行

**概念**：反连接（anti join）是找出"在一张表里、但在另一张表里没有对应记录"的行，常用 LEFT JOIN（或 RIGHT JOIN）加 WHERE 另一边的连接列 IS NULL 实现

**一句话**：外连接没匹配上时，另一边的所有列都是 NULL，所以 LEFT JOIN B ... WHERE B.key IS NULL 就能找出 A 有、B 没有的行；判断时要用连接列或主键这类不会为 NULL 的列，不能用本来就可能为 NULL 的普通列；同样的需求也可以用 NOT EXISTS 写。

**详细解释**：
课件韦恩图：SELECT <select_list> FROM TableA A LEFT JOIN TableB B ON A.Key = B.Key WHERE B.Key IS NULL（只要 A 去掉交集的部分）；RIGHT JOIN ... WHERE A.Key IS NULL（只要 B 去掉交集的部分）；FULL OUTER JOIN ... WHERE A.Key IS NULL OR B.Key IS NULL（两边各自独有的部分）。
课件例子：查没人选的课：
```sql
SELECT *
FROM ENROLL e
RIGHT JOIN COURSE c ON e.CRN = c.CRN
WHERE e.CRN IS NULL;
```
结果只有 NULL NULL 234 COMP 533 一行。
典型需求：没下过单的客户、没有员工的部门、没被引用的商品。
等价写法：WHERE NOT EXISTS (SELECT 1 FROM enroll e WHERE e.crn = c.crn)。不要用 NOT IN，子查询结果里有 NULL 时会一行都查不出来。

**问题**：怎么查出"在 A 表中但在 B 表中没有对应记录"的行？

**答案要点**：
1. A LEFT JOIN B ON 连接条件 WHERE B.连接列 IS NULL
2. 没匹配上时 B 的所有列都是 NULL，用连接列判断最可靠
3. 不能用 B 中本来就可能为 NULL 的普通列判断
4. 也可以写成 NOT EXISTS 相关子查询
5. 避免用 NOT IN，子查询里有 NULL 时结果为空

**常见陷阱**：
- ❌ 用 WHERE e.grade IS NULL 判断学生有没有选课
- ✅ 选了课但还没出成绩的学生 grade 也是 NULL，会被误判；要用 e.netid IS NULL
- ❌ 把 IS NULL 条件写进 ON：LEFT JOIN e ON s.netid = e.netid AND e.netid IS NULL
- ✅ 这样所有学生都配不上，全部保留，起不到过滤作用；IS NULL 要写在 WHERE 里

**追问**：
- Q: LEFT JOIN ... IS NULL 和 NOT EXISTS 哪个好？
- A: 结果相同，MySQL 8.0 的优化器通常会把两者都优化成反连接，性能差不多；NOT EXISTS 语义更直观，LEFT JOIN 写法在老版本里更常见

### 自连接（Self Join）

**概念**：自连接是同一张表和自己做 JOIN，给这张表起两个不同的别名，当成两张表使用，常用于表内的层级关系，比如员工和经理

**一句话**：同一张表用两个别名（F 和 MGR），按 F.MGRNETID = MGR.NETID 连接就能查出每个人的经理；用 INNER JOIN 时没有经理的人（MGRNETID 是 NULL）不会出现，想列出所有人要用 LEFT JOIN；不起别名时 MySQL 会报 Not unique table/alias。

**详细解释**：
Self Join is used when a JOIN is used on the same table。
课件例子：FACULTY(NETID, NAME, MGRNETID)：rbm2 Risa bcd2；abc1 Andre bcd2；bcd2 Betty cde4；cde4 Chris NULL。
```sql
SELECT F.NAME AS EMPLOYEE, MGR.NAME AS MANAGER
FROM FACULTY F JOIN FACULTY MGR
ON F.MGRNETID = MGR.NETID;
```
结果：Andre Betty；Betty Chris；Risa Betty。Chris 没有经理，不在结果里。
别名 F 表示"员工"这一份，MGR 表示"经理"这一份；连接方向反了（F.NETID = MGR.MGRNETID）就会变成"每个人和他的下属"。
这种表叫自引用表：MGRNETID 引用同一张表的主键 NETID，是一元（unary）的一对多关系。

**问题**：什么是自连接？怎么查出每个员工的经理？

**答案要点**：
1. 自连接是同一张表和自己连接
2. 必须给两份表起不同的别名，区分"员工"和"经理"
3. 连接条件：员工.经理编号 = 经理.编号
4. INNER JOIN 会漏掉没有经理的人，要全部列出用 LEFT JOIN
5. 常用于层级结构：员工 - 经理、分类 - 父分类

**常见陷阱**：
- ❌ 用 INNER JOIN 列出"所有员工和经理"
- ✅ 最高层的人经理是 NULL，会被漏掉，要用 LEFT JOIN
- ❌ 写成 ON F.NETID = MGR.MGRNETID 还以为查的是经理
- ✅ 方向反了，查出来的是每个人的下属

**追问**：
- Q: 自连接能查出所有层级的上级（经理的经理……）吗？
- A: 一次自连接只能往上查一层，查多层要连多次；层级不固定时用 MySQL 8.0 的递归 CTE（WITH RECURSIVE）

### FULL OUTER JOIN 及其在 MySQL 中的实现

**概念**：FULL OUTER JOIN 保留两张表的所有行，能匹配的拼在一起，任何一边没有匹配的行另一边填 NULL；MySQL 不支持 FULL OUTER JOIN，用 LEFT JOIN 和 RIGHT JOIN 的结果做 UNION 来实现

**一句话**：MySQL 里写 A LEFT JOIN B UNION A RIGHT JOIN B 模拟全外连接；必须用 UNION 去重，因为两边都匹配的行在左右两个结果里各出现一次；想用更快的 UNION ALL，第二段要加 WHERE A.key IS NULL，只取右表独有的行。

**详细解释**：
Full Outer (MySQL doesn't support)：Display ALL values, matching and non-matching (In MySQL it can be achieved by using left join and right join)。
Used to match up tuples from different relations；Includes all the relations from both sides（这里的 relations 应该是 tuples，两边的行都保留）；If there is no matching tuple, shows NULL。
课件例子：STUDENT(ghi8 Gary, hij2 Holly, ijk12 Isabel)，TEAM(Peanut butter 队长 ghi8，Jelly 队长 NULL)：
```sql
SELECT s.NAME, t.TEAMNAME
FROM STUDENT s LEFT OUTER JOIN TEAM t ON s.NETID = t.CAPTAINNETID
UNION
SELECT s.NAME, t.TEAMNAME
FROM STUDENT s RIGHT OUTER JOIN TEAM t ON s.NETID = t.CAPTAINNETID;
```
结果 4 行：Gary Peanut butter；NULL Jelly；Holly NULL；Isabel NULL（课件结果表的第二列表头写成了 NAME，应为 TEAMNAME）。
UNION ALL 写法：LEFT JOIN 的结果 UNION ALL（RIGHT JOIN ... WHERE s.NETID IS NULL），避免去重的开销。
PostgreSQL、SQL Server、Oracle 支持 FULL OUTER JOIN；MySQL 8.x 仍然不支持。

**问题**：MySQL 不支持 FULL OUTER JOIN，怎么实现？

**答案要点**：
1. FULL OUTER JOIN 保留两边所有行，没匹配的一边填 NULL
2. MySQL 用 LEFT JOIN 结果 UNION RIGHT JOIN 结果实现
3. 必须用 UNION 去重，两边都匹配的行会在两段里各出现一次
4. 用 UNION ALL 时，第二段只取右表独有的行（WHERE 左表键 IS NULL）
5. 两段 SELECT 的列数、列顺序要一致

**对比**：
| 写法 | Gary Peanut butter 出现几次 | 结果行数 |
|---|---|---|
| LEFT JOIN UNION RIGHT JOIN | 1 | 4 |
| LEFT JOIN UNION ALL RIGHT JOIN | 2 | 5 |
| LEFT JOIN UNION ALL (RIGHT JOIN WHERE s.NETID IS NULL) | 1 | 4 |

**常见陷阱**：
- ❌ 在 MySQL 里直接写 FULL OUTER JOIN
- ✅ MySQL 不支持，会报语法错误，要用 LEFT JOIN UNION RIGHT JOIN
- ❌ 为了快把 UNION 换成 UNION ALL，其他不改
- ✅ 两边都匹配的行会重复，要同时给第二段加 WHERE 左表键 IS NULL

**追问**：
- Q: 用 UNION 模拟全外连接，有没有可能把本来就重复的行也去掉？
- A: 有可能：如果左表本身就有两行完全相同的数据，UNION 会把它们合并成一行；用 UNION ALL 加 IS NULL 条件的写法能保留这种重复

**代码题**：下面 SQL 执行后，最后一条查询的结果是什么？

```sql
CREATE TABLE student (netid VARCHAR(10), name VARCHAR(20));
CREATE TABLE team (teamname VARCHAR(20), captainnetid VARCHAR(10));
INSERT INTO student VALUES ('ghi8', 'Gary'), ('hij2', 'Holly'), ('ijk12', 'Isabel');
INSERT INTO team VALUES ('Peanut butter', 'ghi8'), ('Jelly', NULL);
SELECT COUNT(*) FROM (SELECT s.name, t.teamname FROM student s LEFT JOIN team t ON s.netid = t.captainnetid UNION ALL SELECT s.name, t.teamname FROM student s RIGHT JOIN team t ON s.netid = t.captainnetid) x;
```

- [ ] 4
- [x] 5
- [ ] 3
- [ ] 6

解析：LEFT JOIN 3 行 + RIGHT JOIN 2 行，UNION ALL 不去重，Gary Peanut butter 出现了两次，共 5 行；换成 UNION 才是正确的全外连接结果 4 行。

**判断题**：
- ✅ MySQL 不支持 FULL OUTER JOIN，可以把 LEFT JOIN 和 RIGHT JOIN 的结果用 UNION 合并来实现 —— 课件原话：In MySQL it can be achieved by using left join and right join
- ❌ 直接用 UNION ALL 合并 LEFT JOIN 和 RIGHT JOIN 的结果，就和 FULL OUTER JOIN 完全一样 —— 两边都匹配的行会出现两次，要用 UNION，或者给第二段加 WHERE 左表键 IS NULL
