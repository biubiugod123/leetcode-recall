# 集合运算

### UNION 与 UNION ALL

**概念**：UNION 把两个 SELECT 的结果合并成一个结果集并去掉重复行，UNION ALL 合并但不去重；两个 SELECT 的列数必须相同、对应列的类型应当一致，结果的列名取自第一个 SELECT

**一句话**：UNION 去重（要排序或哈希，比较慢），UNION ALL 原样保留所有行（快）；去重是对整个结果做的，连同一个 SELECT 内部的重复行也会去掉；列数不同直接报错；ORDER BY 写在最后，对整个结果排序，用第一个 SELECT 的列名或别名。

**详细解释**：
Set Operations：Results are unordered. It could be useful to perform operations on these: Union、Intersection、Difference；Different RDBMS provide different levels of support。
UNION - eliminates duplicates；UNION ALL - does NOT eliminate duplicates；Uses the column names from the first result set；Data types must match；Number of attributes must match。
课件例子：R(RName) = {Risa, Chris, Bob, Sarah}，S(SName) = {Risa, John, Jorge, Max, Chris}：
```sql
SELECT * FROM R
UNION
SELECT * FROM S;
```
R UNION S 有 7 行（Risa、Chris 只留一份），R UNION ALL S 有 9 行，结果的列名都是 RName。
MySQL 里对应列类型不同时不会报错，会按所有值推断出结果列的类型（隐式转换），但最好保持一致。
要对某一个 SELECT 单独排序或 LIMIT，MySQL 要求把它放进括号里；写在最后的 ORDER BY / LIMIT 作用于整个 UNION 结果。

**问题**：UNION 和 UNION ALL 有什么区别？使用时有什么要求？

**答案要点**：
1. UNION 去掉重复行，UNION ALL 保留所有行
2. UNION 要去重，性能比 UNION ALL 差；确定没有重复或允许重复时用 UNION ALL
3. 各个 SELECT 的列数必须相同，对应列的类型应当一致
4. 结果的列名取自第一个 SELECT
5. ORDER BY 写在最后，对整个结果排序

**对比**：
| | UNION | UNION ALL |
|---|---|---|
| 重复行 | 去掉 | 保留 |
| 性能 | 慢（要去重） | 快 |
| R(4 行) 和 S(5 行) 有 2 个相同 | 7 行 | 9 行 |
| 适用 | 需要集合语义 | 明确不会重复，或者重复有意义 |

**常见陷阱**：
- ❌ 以为 UNION 只去掉"两边之间"的重复
- ✅ UNION 对整个结果去重，第一个表自己内部的重复行也会被合并
- ❌ 在 UNION 之后的 ORDER BY 里用第二个 SELECT 的列名
- ✅ 结果的列名来自第一个 SELECT，ORDER BY 应该用第一个 SELECT 的列名或别名

**追问**：
- Q: 为什么能用 UNION ALL 时尽量不用 UNION？
- A: UNION 要对整个结果做排序或哈希去重，数据量大时会用到临时表，开销明显；如果两边本来就不会有重复（比如按不同条件拆开的同一张表），UNION ALL 结果一样但更快

**代码题**：下面 SQL 执行后，最后一条查询的结果是什么？

```sql
CREATE TABLE r (rname VARCHAR(10));
CREATE TABLE s (sname VARCHAR(10));
INSERT INTO r VALUES ('Risa'), ('Chris'), ('Bob'), ('Sarah');
INSERT INTO s VALUES ('Risa'), ('John'), ('Jorge'), ('Max'), ('Chris');
SELECT (SELECT COUNT(*) FROM (SELECT rname FROM r UNION SELECT sname FROM s) t1), (SELECT COUNT(*) FROM (SELECT rname FROM r UNION ALL SELECT sname FROM s) t2);
```

- [x] 7 9
- [ ] 9 9
- [ ] 7 7
- [ ] 9 7

解析：Risa 和 Chris 两边都有，UNION 去重后 4 + 5 - 2 = 7 行；UNION ALL 全部保留，4 + 5 = 9 行。

**代码题**：下面 SQL 执行后，最后一条查询的结果是什么？（每行用 | 隔开）


解析：两边之间没有相同的值，但 r 自己有两个 Bob；UNION 对整个结果去重，只留一个 Bob；ORDER BY 作用于整个结果，用的是第一个 SELECT 的列名 rname。

**代码题**：下面 SQL 执行结果是什么？

```sql
CREATE TABLE r (rname VARCHAR(10), age INT);
CREATE TABLE s (sname VARCHAR(10));
INSERT INTO r VALUES ('Bob', 20);
INSERT INTO s VALUES ('Max');
SELECT rname, age FROM r UNION SELECT sname FROM s;
```

- [ ] Bob 20 | Max NULL
- [ ] Bob 20 | Max
- [x] 执行报错
- [ ] 查询结果为空

解析：第一个 SELECT 有 2 列，第二个只有 1 列，列数不同，UNION 直接报错，不会自动补 NULL；需要的话要在第二个 SELECT 里显式写 SELECT sname, NULL。

**判断题**：
- ✅ UNION 结果集的列名取自第一个 SELECT 语句 —— 课件：Uses the column names from the first result set
- ❌ UNION ALL 会自动去掉结果中的重复行 —— UNION ALL 不去重，去重的是 UNION

### 交集（INTERSECT）

**概念**：交集返回同时出现在两个查询结果中的行；标准 SQL 用 INTERSECT，MySQL 从 8.0.31 才支持，之前的版本用 INNER JOIN 或 IN 子查询实现

**一句话**：课件说 MySQL 不直接支持交集，可以用 INNER JOIN 实现（这是 8.0.31 之前的情况）；INTERSECT 自带去重，而 INNER JOIN 遇到重复值会产生重复行，要加 DISTINCT；也可以写成 SELECT DISTINCT ... WHERE x IN (SELECT ...)。

**详细解释**：
Intersection：MySQL doesn't support intersection directly, but INNER JOIN can be used to implement intersection。
```sql
SELECT R.RName
FROM R
INNER JOIN S ON R.RName = S.SName;
```
课件结果：Chris、Risa。
MySQL 8.0.31+：SELECT RName FROM R INTERSECT SELECT SName FROM S;
INNER JOIN 写法的两个差别：一是重复值会相乘（R 里有两个 Chris，结果就有两个 Chris），要 SELECT DISTINCT；二是 INTERSECT 把两个 NULL 视为相同，而 JOIN 的 = 遇到 NULL 不成立。
多列交集：INNER JOIN 的 ON 里把每一列都写成相等条件，或者用 (a, b) IN (SELECT a, b ...)。

**问题**：MySQL 怎么求两个查询结果的交集？

**答案要点**：
1. MySQL 8.0.31 起支持 INTERSECT
2. 旧版本用 INNER JOIN 按所有列相等连接
3. 或者用 SELECT DISTINCT ... WHERE x IN (子查询)
4. INNER JOIN 写法遇到重复值会产生重复行，要加 DISTINCT
5. INTERSECT 自带去重，并且把 NULL 当作相同的值

**常见陷阱**：
- ❌ 用 INNER JOIN 求交集，不加 DISTINCT
- ✅ 某一边有重复值时结果也会重复，INTERSECT 的语义是集合，要 SELECT DISTINCT
- ❌ 两个结果都有多列（比如姓名 + 生日），用 INNER JOIN 求交集时只在 ON 里比较了姓名
- ✅ 交集要求整行相同，ON 里要把每一列都写成相等条件

**追问**：
- Q: 求交集用 INNER JOIN 好还是 IN 子查询好？
- A: 结果一样（加了 DISTINCT 的话），MySQL 的优化器会把 IN 子查询转成半连接（semi-join），一般性能相近；IN 写法天然不会因为右边的重复而产生重复行

**代码题**：下面 SQL 执行后，最后一条查询的结果是什么？（每行用 | 隔开）

```sql
CREATE TABLE r (rname VARCHAR(10));
CREATE TABLE s (sname VARCHAR(10));
INSERT INTO r VALUES ('Risa'), ('Chris'), ('Bob'), ('Chris');
INSERT INTO s VALUES ('Risa'), ('John'), ('Chris');
SELECT r.rname FROM r INNER JOIN s ON r.rname = s.sname ORDER BY r.rname;
```

- [x] Chris | Chris | Risa
- [ ] Chris | Risa
- [ ] Bob | Chris | Risa
- [ ] Risa

解析：r 里有两个 Chris，各自和 s 的 Chris 匹配一次，所以结果有两行 Chris；要得到集合意义上的交集，写 SELECT DISTINCT r.rname，或者用 INTERSECT。

**判断题**：
- ✅ MySQL 8.0.31 之前不支持 INTERSECT，可以用 INNER JOIN 或 IN 子查询实现交集 —— 课件：INNER JOIN can be used to implement intersection
- ❌ 用 INNER JOIN 实现交集时，结果会像 INTERSECT 一样自动去重 —— INNER JOIN 遇到重复值会产生重复行，需要 DISTINCT

### 差集（EXCEPT）

**概念**：差集返回在第一个查询结果中、但不在第二个查询结果中的行；标准 SQL 用 EXCEPT（Oracle 叫 MINUS），MySQL 从 8.0.31 才支持，之前用 NOT EXISTS 或 LEFT JOIN ... IS NULL 实现

**一句话**：R EXCEPT S 就是 R 减去在 S 里出现过的值，不满足交换律；旧版本 MySQL 用 NOT EXISTS 或者 LEFT JOIN 加 WHERE 右表列 IS NULL；不要用 NOT IN，S 的结果里只要有一个 NULL，NOT IN 就一行都查不出来。

**详细解释**：
Difference Implemented via EXCEPT：Display the values in the first select statement MINUS any values found in the second select statement。
```sql
SELECT * FROM R
EXCEPT
SELECT * FROM S;
```
课件结果：Bob、Sarah（课件截图来自 SQL Server；MySQL 8.0.31 起才支持 EXCEPT）。
旧版本写法：
```sql
SELECT r.RName FROM R r
WHERE NOT EXISTS (SELECT 1 FROM S s WHERE s.SName = r.RName);

SELECT r.RName FROM R r
LEFT JOIN S s ON r.RName = s.SName
WHERE s.SName IS NULL;
```
NOT IN 的问题：x NOT IN (a, NULL) 等价于 x <> a AND x <> NULL，后半部分永远是 UNKNOWN，整个条件不可能为 TRUE；NOT EXISTS 只看有没有匹配的行，不受 NULL 影响。

**问题**：MySQL 怎么求差集？为什么不推荐用 NOT IN？

**答案要点**：
1. 差集：在第一个结果中、不在第二个结果中的行；MySQL 8.0.31 起支持 EXCEPT
2. 旧版本用 NOT EXISTS 相关子查询
3. 或者用 LEFT JOIN ... WHERE 右表列 IS NULL
4. NOT IN 遇到子查询结果里有 NULL 时，结果为空
5. 差集不满足交换律，R - S 和 S - R 不同

**对比**：
| 写法 | 子查询结果里有 NULL 时 |
|---|---|
| NOT IN (SELECT ...) | 一行都查不出来 |
| NOT EXISTS (SELECT ... WHERE 相等) | 正常 |
| LEFT JOIN ... WHERE 右表列 IS NULL | 正常 |
| EXCEPT（8.0.31+） | 正常，并且自带去重 |

**常见陷阱**：
- ❌ 用 WHERE rname NOT IN (SELECT sname FROM s) 求差集
- ✅ s.sname 里有 NULL 时结果为空，改用 NOT EXISTS，或者在子查询里加 WHERE sname IS NOT NULL
- ❌ 以为 R EXCEPT S 和 S EXCEPT R 一样
- ✅ R - S = {Bob, Sarah}，S - R = {John, Jorge, Max}

**追问**：
- Q: NOT IN 一定不能用吗？
- A: 子查询的列定义为 NOT NULL，或者子查询里过滤掉了 NULL，NOT IN 就是安全的；但不能保证时用 NOT EXISTS 更稳

**代码题**：下面 SQL 执行后，最后一条查询的结果是什么？（每行用 | 隔开）

```sql
CREATE TABLE r (rname VARCHAR(10));
CREATE TABLE s (sname VARCHAR(10));
INSERT INTO r VALUES ('Risa'), ('Chris'), ('Bob'), ('Sarah');
INSERT INTO s VALUES ('Risa'), ('John'), ('Jorge'), ('Max'), ('Chris');
SELECT r.rname FROM r LEFT JOIN s ON r.rname = s.sname WHERE s.sname IS NULL ORDER BY r.rname;
```

- [x] Bob | Sarah

解析：LEFT JOIN 后，Risa、Chris 在 s 里有匹配，Bob、Sarah 没有，右边是 NULL；WHERE s.sname IS NULL 留下 R 独有的值，就是 R - S。

**代码题**：下面 SQL 执行后，最后一条查询的结果是什么？（每行用 | 隔开）

```sql
CREATE TABLE r (rname VARCHAR(10));
CREATE TABLE s (sname VARCHAR(10));
INSERT INTO r VALUES ('Risa'), ('Chris'), ('Bob'), ('Sarah');
INSERT INTO s VALUES ('Risa'), ('Chris'), (NULL);

```

- [ ] Bob | Sarah
- [ ] Bob | NULL | Sarah

- [ ] 执行报错

解析：对 Bob 来说，条件是 'Bob' <> 'Risa' AND 'Bob' <> 'Chris' AND 'Bob' <> NULL，最后一项是 UNKNOWN，整个条件不是 TRUE；每一行都这样，所以结果为空。

**代码题**：下面 SQL 执行后，最后一条查询的结果是什么？（每行用 | 隔开）

```sql
CREATE TABLE r (rname VARCHAR(10));
CREATE TABLE s (sname VARCHAR(10));
INSERT INTO r VALUES ('Risa'), ('Chris'), ('Bob'), ('Sarah');
INSERT INTO s VALUES ('Risa'), ('Chris'), (NULL);
SELECT rname FROM r WHERE NOT EXISTS (SELECT 1 FROM s WHERE s.sname = r.rname) ORDER BY rname;
```

- [x] Bob | Sarah
- [ ] 查询结果为空
- [ ] Chris | Risa
- [ ] Bob | NULL | Sarah

解析：NOT EXISTS 只看子查询有没有返回行：Bob、Sarah 在 s 里找不到相等的值，子查询为空，NOT EXISTS 为真；s 里的 NULL 和谁都不相等，不影响结果。

**判断题**：
- ✅ R EXCEPT S 返回在 R 中出现、但不在 S 中出现的行 —— 课件：the values in the first select statement MINUS any values found in the second select statement
- ❌ R EXCEPT S 和 S EXCEPT R 的结果相同 —— 差集不满足交换律，课件例子中 R - S = {Bob, Sarah}，S - R = {John, Jorge, Max}
