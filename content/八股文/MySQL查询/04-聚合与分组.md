# 聚合与分组

### 聚合函数与 NULL

**概念**：聚合函数（COUNT、AVG、SUM、MAX、MIN）把多行数据汇总成一个值；COUNT(*) 统计所有行，其他聚合函数和 COUNT(列) 都会忽略 NULL

**一句话**：COUNT(*) 和 COUNT(1) 数所有行（包括 NULL），COUNT(列) 只数非 NULL，COUNT(DISTINCT 列) 去重后再数；AVG 是非 NULL 值的和除以非 NULL 值的个数，不是除以总行数；一行数据都没有时，COUNT 返回 0，而 SUM、AVG、MAX、MIN 返回 NULL，需要 0 时用 COALESCE(SUM(x), 0)。

**详细解释**：
Aggregate functions are built-in functions that used to perform simple statistics：COUNT()、AVG()、SUM()、MAX()、MIN()。
The COUNT() function returns the number of rows that matches a specified criterion；The AVG() function returns the average value of a numeric column；The SUM() function returns the total sum；The MIN() and MAX() functions return the smallest and largest values of the selected columns respectively。
How does aggregate functions handle NULL value?：COUNT(*) or COUNT(1) gives the total number of records in the table including NULL values；COUNT(column_name) counts rows where the column contains a Not-NULL value；AVG, MIN, MAX, etc. ignore NULL values；GROUP BY includes a row for null。
例子：score 为 2、1、NULL、4、5 时，COUNT(*) = 5，COUNT(score) = 4，SUM = 12，AVG = 12 / 4 = 3（如果想把 NULL 当 0 算，要写 AVG(COALESCE(score, 0)) = 12 / 5）。
MySQL 对整数列求 AVG 返回 DECIMAL（默认保留 4 位小数，比如 3.3333），SUM 整数列返回 DECIMAL。

**问题**：聚合函数是怎么处理 NULL 的？没有任何行时聚合函数返回什么？

**答案要点**：
1. COUNT(*) / COUNT(1) 统计所有行，包括含 NULL 的行
2. COUNT(列) 只统计该列非 NULL 的行，COUNT(DISTINCT 列) 先去重
3. SUM、AVG、MAX、MIN 都忽略 NULL；AVG 的分母是非 NULL 值的个数
4. 没有行时 COUNT 返回 0，SUM / AVG / MAX / MIN 返回 NULL
5. 需要默认值时用 COALESCE(SUM(x), 0)

**对比**：
| 表达式 | score 为 2、1、NULL、4、5 | 没有任何行 |
|---|---|---|
| COUNT(*) | 5 | 0 |
| COUNT(score) | 4 | 0 |
| SUM(score) | 12 | NULL |
| AVG(score) | 3（12 / 4） | NULL |
| MAX(score) | 5 | NULL |

**常见陷阱**：
- ❌ 以为 AVG 会把 NULL 当成 0 参与计算
- ✅ AVG 忽略 NULL，分母只算非 NULL 的行；要当 0 算得写 AVG(COALESCE(score, 0))
- ❌ 以为没有数据时 SUM 返回 0
- ✅ SUM 返回 NULL，程序里直接用可能出空指针，要写 COALESCE(SUM(x), 0)

**追问**：
- Q: COUNT(*)、COUNT(1)、COUNT(主键) 有区别吗？
- A: 结果都是总行数；在 MySQL InnoDB 中 COUNT(*) 和 COUNT(1) 的处理方式相同，优化器会选最小的索引来数；COUNT(可为 NULL 的列) 才会不一样

- ✅ AVG 计算平均值时会忽略 NULL —— 课件：AVG, MIN, MAX, etc. ignore NULL values，分母只算非 NULL 的行

### GROUP BY 分组规则

**概念**：GROUP BY 把某一列（或多列）值相同的行分成一组，常和聚合函数一起使用，对每一组分别统计；SELECT 中没有被聚合的列都必须出现在 GROUP BY 里

**一句话**：每个分组在结果里只有一行，所以 SELECT 里只能放分组列和聚合函数，否则一组里有多个不同的值不知道显示哪个（MySQL 5.7 起默认开启 ONLY_FULL_GROUP_BY，会直接报错）；可以按多列分组，组合相同才算一组；分组列里的 NULL 会单独成为一组，多个 NULL 归到同一组。

**详细解释**：
The GROUP BY clause is used to form the groups of records；It is often used with aggregate functions to group the result set by one or more columns；Any non-aggregate columns called in the SELECT statement must be in group by（课件用红字强调）。
课件问题：What is the average rating for each coffee? RATES(ID, DRINKER, COFFEE, SCORE)：
```sql
SELECT coffee, AVG(score)
FROM rates
GROUP BY coffee;
```
结果：Cold Brew 3.3333（(1 + 4 + 5) / 3）；Espresso 2.0000；Turkish Coffee 5.0000。
ONLY_FULL_GROUP_BY：SELECT drinker, coffee, AVG(score) ... GROUP BY coffee 会报错，因为 Cold Brew 这一组里 drinker 有 Aiden 和 Ivan 两个值；MySQL 允许 SELECT 中出现"函数依赖于分组列"的列（比如按主键分组时选同一行的其他列）。
GROUP BY 多列：GROUP BY drinker, coffee 表示 (drinker, coffee) 的组合相同才是一组。
NULL：GROUP BY 把所有 NULL 视为同一组；这一组的 COUNT(分组列) 是 0，因为 COUNT(列) 不数 NULL。

**问题**：使用 GROUP BY 时 SELECT 里能写哪些列？NULL 会怎么分组？

**答案要点**：
1. GROUP BY 把分组列值相同的行合成一组，每组输出一行
2. SELECT 里只能写分组列和聚合函数（以及依赖于分组列的列）
3. MySQL 5.7 起默认 ONLY_FULL_GROUP_BY，违反会报错
4. 可以按多列分组，组合相同才是同一组
5. NULL 单独成为一组，所有 NULL 在同一组

**对比**：
| 写法 | 每组 | 结果行数（课件 RATES） |
|---|---|---|
| GROUP BY coffee | 一种咖啡 | 3 |
| GROUP BY drinker | 一个人 | 2 |
| GROUP BY drinker, coffee | 一个人 + 一种咖啡 | 4 |

**常见陷阱**：
- ❌ SELECT drinker, coffee, AVG(score) FROM rates GROUP BY coffee
- ✅ drinker 既没聚合也没分组，开启 ONLY_FULL_GROUP_BY 时报错；关掉后会随便取一个值，结果不可靠
- ❌ 以为 GROUP BY 会把 NULL 的行丢掉
- ✅ NULL 会单独成为一组（课件：GROUP BY includes a row for null）

**追问**：
- Q: GROUP BY 之后结果一定是按分组列排好序的吗？
- A: 不一定；MySQL 8.0 起 GROUP BY 不再隐式排序，需要顺序时必须写 ORDER BY

### HAVING 与 WHERE 的配合

**概念**：WHERE 在分组之前过滤原始行，HAVING 在分组之后过滤分组；一条查询可以同时使用两者，HAVING 中可以使用聚合函数，WHERE 中不行

**一句话**：执行时先 WHERE 去掉不需要的行，再 GROUP BY 分组、算聚合，然后 HAVING 去掉不满足条件的组；所以 WHERE 改变的是参与统计的数据，HAVING 改变的是留下哪些组；HAVING 里可以用多个聚合条件组合，ORDER BY 里也可以直接按聚合值排序。

**详细解释**：
Having clause is used to filter out grouping records, it's like the WHERE clause. The difference is WHERE clause CANNOT be used with aggregate functions, whereas Having clause can work with；Having clause MUST come after GROUP BY clause and before ORDER BY clause。
课件问题：What is the highest rated type of coffee, on average, considering only coffees that have at least 3 ratings.
```sql
SELECT coffee, AVG(score) AS avg_score
FROM rates
GROUP BY coffee
HAVING COUNT(*) >= 3
ORDER BY avg_score DESC
LIMIT 1;
```
结果：Cold Brew 3.3333；Turkish Coffee 平均 5 分最高，但只有 1 条评分，被 HAVING 过滤掉。
同一个条件如果不涉及聚合（比如 coffee <> 'Mocha'），写在 WHERE 里更好：先减少行数，分组的工作量更小。
WHERE score >= 4 和 HAVING MIN(score) >= 4 不一样：前者是只拿高分评分去统计，后者是只保留"所有评分都 ≥ 4"的组。

**问题**：一条查询里同时有 WHERE 和 HAVING 时是怎么执行的？

**答案要点**：
1. 先 WHERE 过滤原始行，不能用聚合函数
2. 再 GROUP BY 分组并计算聚合值
3. 然后 HAVING 过滤分组，可以用聚合函数，也可以组合多个聚合条件
4. HAVING 写在 GROUP BY 之后、ORDER BY 之前
5. 不涉及聚合的条件尽量写在 WHERE 里，减少参与分组的行

**对比**：
| 写法 | 含义 | 课件 RATES 的结果 |
|---|---|---|
| WHERE score >= 4 GROUP BY coffee | 只统计 4 分以上的评分 | Cold Brew 2 条、Turkish Coffee 1 条 |
| GROUP BY coffee HAVING MIN(score) >= 4 | 只保留所有评分都 ≥ 4 的咖啡 | Turkish Coffee |
| GROUP BY coffee HAVING COUNT(*) >= 3 | 只保留评分数 ≥ 3 的咖啡 | Cold Brew |

**常见陷阱**：
- ❌ 把"至少 3 条评分"写成 WHERE COUNT(*) >= 3
- ✅ WHERE 执行时还没分组，聚合条件必须写在 HAVING 里
- ❌ 以为先 WHERE 再 HAVING 和只写 HAVING 结果一样
- ✅ WHERE 去掉的行不参与统计，COUNT、SUM 的值都会变

**追问**：
- Q: 不写 GROUP BY 能用 HAVING 吗？
- A: 可以，这时整张表被当成一组，比如 SELECT COUNT(*) FROM rates HAVING COUNT(*) > 3；但一般没什么必要

### ORDER BY 与 LIMIT

**概念**：ORDER BY 对结果按一列或多列排序，默认升序（ASC），降序用 DESC；LIMIT 限制返回的行数，常和 ORDER BY 一起实现 Top N 和分页

**一句话**：多列排序时 ASC / DESC 只修饰紧挨在它前面的那一列，ORDER BY a DESC, b 中 b 仍是升序；MySQL 升序时 NULL 排在最前面；LIMIT n 取前 n 行，LIMIT n OFFSET m 跳过 m 行再取 n 行，MySQL 的 LIMIT m, n 第一个数是偏移量；排序列有重复值时要加第二排序列，否则顺序不确定。

**详细解释**：
The ORDER BY clause is used to sort the result in ascending or descending order；ORDER BY clause sorts the result in ascending order by default. To sort the result by descending order, use the DESC keyword；The ORDER BY must come after WHERE, GROUP BY, and HAVING clause if present in the query（课件把 GROUP BY 写成了 GROUPBY）；Can be used with LIMIT。
```sql
SELECT column1, column2, ...columnN
FROM table_name
[WHERE]
[GROUP BY]
[HAVING]
ORDER BY column ASC/DESC;
```
求第二高的分数：SELECT DISTINCT score FROM rates ORDER BY score DESC LIMIT 1 OFFSET 1（等价于 LIMIT 1, 1）。
分页：第 p 页、每页 n 条是 LIMIT n OFFSET (p - 1) * n；OFFSET 很大时 MySQL 仍要先扫过前面所有行，深分页要改成"记住上一页最后一个 id，WHERE id > ? LIMIT n"。
没有 ORDER BY 时，结果的顺序是不确定的，不能依赖插入顺序。

**问题**：ORDER BY 多列排序是什么规则？LIMIT 怎么用？

**答案要点**：
1. 默认升序 ASC，降序用 DESC
2. 多列排序先按第一列，相同时再按第二列；ASC / DESC 只作用于紧挨的那一列
3. MySQL 升序时 NULL 排在最前面，降序时排在最后
4. LIMIT n 取前 n 行；LIMIT n OFFSET m 和 LIMIT m, n 都是跳过 m 行取 n 行
5. ORDER BY 写在 WHERE、GROUP BY、HAVING 之后，LIMIT 最后

**对比**：
| 写法 | 含义 |
|---|---|
| ORDER BY drinker DESC, score | drinker 降序，同一个人内部 score 升序 |
| ORDER BY drinker DESC, score DESC | 两列都降序 |
| LIMIT 3 | 前 3 行 |
| LIMIT 3 OFFSET 2 | 跳过 2 行，取 3 行 |
| LIMIT 2, 3 | 同上（MySQL 写法，偏移量在前） |

**常见陷阱**：
- ❌ 以为 ORDER BY a, b DESC 两列都是降序
- ✅ 只有 b 降序，a 仍是默认的升序
- ❌ 把 LIMIT 2, 3 理解成"取第 2 到第 3 行"
- ✅ 是跳过 2 行，再取 3 行（第 3 到第 5 行）

**追问**：
- Q: 怎么求第二高的分数？如果最高分有并列呢？
- A: SELECT DISTINCT score ... ORDER BY score DESC LIMIT 1 OFFSET 1，DISTINCT 保证并列的最高分只算一个；如果不存在第二高，结果为空，需要 NULL 时可以把它包成标量子查询 SELECT (SELECT ...)

### SQL 语句的执行顺序

**概念**：SQL 的书写顺序是 SELECT → FROM → WHERE → GROUP BY → HAVING → ORDER BY，而逻辑上的处理顺序是 FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY，加上 DISTINCT 和 LIMIT 时，DISTINCT 在 SELECT 之后，LIMIT 最后

**一句话**：先 FROM / JOIN 确定数据来源，WHERE 过滤行，GROUP BY 分组，HAVING 过滤组，然后才 SELECT 计算列和别名，接着 DISTINCT 去重、ORDER BY 排序，最后 LIMIT 截取；所以 WHERE 不能用聚合函数和 SELECT 里的别名，ORDER BY 可以用别名，LIMIT 是在排好序的结果上取前几行。

**详细解释**：
课件 DQL Execution Order 表：Logic 列是 SELECT、FROM、WHERE、GROUP BY、HAVING、ORDER BY；Actual 列是 FROM、WHERE、GROUP BY、HAVING、SELECT、ORDER BY。
课件表头的 Logic 指的是"书写顺序"，Actual 才是平常说的逻辑处理顺序（logical query processing order），容易看反。
完整顺序：
```
FROM / JOIN ... ON → WHERE → GROUP BY → HAVING → SELECT → DISTINCT → ORDER BY → LIMIT
```
推论：WHERE 里不能用 COUNT 等聚合函数（还没分组）；WHERE 里不能用 SELECT 的列别名（MySQL 报 Unknown column）；HAVING、ORDER BY 在分组之后，可以用聚合函数；ORDER BY 在 SELECT 之后，可以用别名；LIMIT 最后执行，先排序再截取。
这是逻辑顺序：优化器实际执行时可以调整（比如把条件下推、用索引避免排序），但结果必须和逻辑顺序一致。

**问题**：SQL 语句的执行顺序是怎样的？为什么 WHERE 不能用 SELECT 中的别名？

**答案要点**：
1. 书写顺序：SELECT、FROM、WHERE、GROUP BY、HAVING、ORDER BY、LIMIT
2. 处理顺序：FROM → WHERE → GROUP BY → HAVING → SELECT → DISTINCT → ORDER BY → LIMIT
3. WHERE 在 SELECT 之前，不能用 SELECT 的别名，也不能用聚合函数
4. ORDER BY 在 SELECT 之后，可以用别名
5. LIMIT 最后执行，所以总是对排好序的结果截取

**对比**：
| 子句 | 能用聚合函数 | 能用 SELECT 别名（MySQL） |
|---|---|---|
| WHERE | 不能 | 不能 |
| GROUP BY | 不能 | 能（MySQL 扩展） |
| HAVING | 能 | 能（MySQL 扩展） |
| ORDER BY | 能 | 能 |

**常见陷阱**：
- ❌ 以为 LIMIT 先取出前几行，再对这几行排序
- ✅ ORDER BY 先对全部结果排序，LIMIT 最后截取
- ❌ 在 WHERE 里写 SELECT 中定义的别名，比如 WHERE cnt > 1
- ✅ WHERE 执行时别名还不存在，MySQL 报 Unknown column；要重复写表达式，聚合条件改到 HAVING

**追问**：
- Q: 逻辑执行顺序和数据库真正的执行过程是一回事吗？
- A: 不是；逻辑顺序决定了"结果应该是什么"，优化器可以改变实际的执行方式（比如先走索引过滤、把条件下推到子查询），只要结果相同

**代码题**：下面 SQL 执行后，最后一条查询的结果是什么？（每行用 | 隔开）

```sql
CREATE TABLE rates (id INT, drinker VARCHAR(10), coffee VARCHAR(20), score INT);
INSERT INTO rates VALUES (1, 'Ivan', 'Espresso', 2), (2, 'Aiden', 'Cold Brew', 1), (3, 'Aiden', 'Turkish Coffee', 5), (4, 'Ivan', 'Cold Brew', 4), (5, 'Ivan', 'Cold Brew', 5);
SELECT coffee, COUNT(*) AS cnt FROM rates WHERE score >= 2 GROUP BY coffee ORDER BY cnt DESC, coffee LIMIT 2;
```

- [x] Cold Brew 2 | Espresso 1
- [ ] Cold Brew 3 | Espresso 1
- [ ] Espresso 1 | Turkish Coffee 1
- [ ] Cold Brew 2 | Espresso 1 | Turkish Coffee 1

解析：WHERE 先去掉 1 分那条，Cold Brew 只剩 2 条；分组后按 cnt 降序、cnt 相同再按 coffee 升序：Cold Brew 2、Espresso 1、Turkish Coffee 1；LIMIT 最后执行，取前 2 行。ORDER BY 里用了 SELECT 的别名 cnt。

**判断题**：
- ✅ ORDER BY 子句中可以使用 SELECT 里定义的列别名 —— ORDER BY 在 SELECT 之后执行，别名已经存在
- ❌ SQL 按书写顺序执行，先执行 SELECT 再执行 FROM —— 课件的 Actual 列：先 FROM、WHERE、GROUP BY、HAVING，然后才是 SELECT
