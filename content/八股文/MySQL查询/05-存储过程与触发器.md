# 存储过程与触发器

### 存储过程的概念与优缺点

**概念**：存储过程（Stored Procedure）是一组预先编写好、存放在数据库里的 SQL 语句，用 CREATE PROCEDURE 创建、用 CALL 执行，可以接收输入参数、返回输出参数和结果集

**一句话**：存储过程把多条 SQL 封装成数据库里的一个对象，应用只要 CALL 一下就能执行整段逻辑；好处是减少网络往返、逻辑复用、可以只授予执行权限；坏处是业务逻辑放进数据库后不好调试、不好做版本管理和单元测试，语法和数据库绑定、难以迁移，所以互联网项目里一般少用。

**详细解释**：
A stored procedure is a set of SQL statements that are pre-compiled and stored in the database；To create a stored procedure you need to use CREATE PROCEDURE statement；It accepts input and output parameters (Parameter declaration: IN, OUT)；It executes the SQL statements, and returns a result set if any；To execute a stored procedure you need to use CALL statement。
Benefits of SP：Performance Improvement；Code Reusability。
关于"预编译"：这是 SQL Server 等数据库的说法；MySQL 是在每个连接第一次调用某个存储过程时解析并放进该连接的缓存，之后同一连接再调用不用重新解析，不同连接之间不共享。
性能提升主要来自：一次 CALL 执行多条语句，减少客户端和服务器之间的网络往返；以及解析结果的复用。
安全：可以只给用户 EXECUTE 权限，不给表的直接读写权限，用户只能按存储过程规定的方式操作数据。
存储过程和函数（FUNCTION）的区别：函数必须 RETURN 一个值，可以在 SELECT 里直接调用；存储过程用 CALL 调用，通过 OUT 参数或结果集返回数据。

**问题**：什么是存储过程？有什么优缺点？

**答案要点**：
1. 存储过程是存放在数据库里的一组 SQL，CREATE PROCEDURE 创建，CALL 执行
2. 可以有 IN、OUT 参数，可以返回结果集
3. 优点：减少网络往返、提高性能，代码复用，可以只授予执行权限
4. 缺点：调试和版本管理困难，和具体数据库绑定、难迁移，业务逻辑分散
5. 和函数的区别：函数 RETURN 一个值并可以在 SQL 表达式中使用，存储过程用 CALL 调用

**对比**：
| | 存储过程 | 函数 | 应用代码里的 SQL |
|---|---|---|---|
| 存放位置 | 数据库 | 数据库 | 应用程序 |
| 调用方式 | CALL | 在 SELECT 等表达式中 | 程序逐条发送 |
| 返回 | OUT 参数、结果集 | 一个返回值 | 每条语句的结果 |
| 网络往返 | 一次 | 随语句 | 每条语句一次 |

**常见陷阱**：
- ❌ 认为把所有业务逻辑都写成存储过程一定更好
- ✅ 存储过程难调试、难测试、难迁移，现在多数项目把业务逻辑放在应用层，只在批量数据处理等场景使用
- ❌ 以为 MySQL 的存储过程在创建时就被编译成机器码
- ✅ MySQL 是在每个连接第一次调用时解析并缓存，"预编译"主要是 SQL Server 的说法

**追问**：
- Q: 存储过程为什么能提高性能？
- A: 一次 CALL 就能在服务器端执行多条语句，省掉了多次网络往返；同一个连接里重复调用时，解析结果会被缓存复用

**判断题**：
- ✅ 存储过程存放在数据库中，用 CREATE PROCEDURE 创建、用 CALL 执行 —— 课件：To create ... use CREATE PROCEDURE；To execute ... use CALL
- ❌ 每次执行存储过程，客户端都要把过程里的全部 SQL 语句重新发送给服务器 —— 存储过程保存在数据库里，客户端只需要发送一条 CALL 语句

### 存储过程的参数与 DELIMITER

**概念**：MySQL 存储过程的参数有三种模式：IN（调用方传入）、OUT（过程内赋值后传回调用方）、INOUT（既传入又传出）；创建时要用 DELIMITER 临时修改语句结束符

**一句话**：IN 参数把值传进过程，OUT 参数用 SELECT ... INTO 赋值，调用时传一个会话变量（@total），CALL 之后用 SELECT @total 读出来；过程体里有多条以分号结尾的语句，所以要先 DELIMITER // 改掉结束符，写完再改回分号；MySQL 的存储过程参数不支持默认值，每个参数调用时都必须传。

**详细解释**：
Parameters for Stored Procedures：Input Parameters：Specify variables to be taken in when using a stored procedure；Output Parameters：Used to output multiple values；Output value can be used in the stored procedure or batch that calls it；Default Parameter：Assigns the parameter with a default value（"batch"和参数默认值都是 SQL Server 的概念，MySQL 的存储过程不支持参数默认值）。
课件例子 1（IN 参数）：
```sql
DELIMITER //
CREATE PROCEDURE GetOfficeByCountry(
    IN countryName VARCHAR(255)
)
BEGIN
    SELECT * FROM offices WHERE country = countryName;
END //
DELIMITER ;

CALL GetOfficeByCountry('USA');
```
返回 San Francisco、Boston、NYC 三个办公室。
课件例子 2（OUT 参数）：
```sql
DELIMITER $$
CREATE PROCEDURE GetOrderCountByStatus (
    IN  orderStatus VARCHAR(25),
    OUT total INT
)
BEGIN
    SELECT COUNT(orderNumber) INTO total FROM orders WHERE status = orderStatus;
END$$
DELIMITER ;

CALL GetOrderCountByStatus('Shipped', @total);
SELECT @total;
```
结果 @total = 303。
DELIMITER 是 mysql 客户端的命令，不是 SQL 语句：客户端看到结束符就把前面的内容发给服务器，不改的话 CREATE PROCEDURE 会在第一个分号处被截断。
@total 是用户定义的会话变量，只在当前连接里有效。

**问题**：MySQL 存储过程有哪几种参数？OUT 参数怎么使用？为什么要写 DELIMITER？

**答案要点**：
1. IN：调用方传入，过程内只读使用
2. OUT：过程内用 SELECT ... INTO 或 SET 赋值，调用方用会话变量接收
3. INOUT：既传入也传出
4. 调用：CALL p('Shipped', @total); 再 SELECT @total;
5. DELIMITER 临时改变客户端的语句结束符，防止过程体中的分号把 CREATE PROCEDURE 截断

**对比**：
| 模式 | 方向 | 调用时传什么 |
|---|---|---|
| IN | 调用方 → 过程 | 值或变量 |
| OUT | 过程 → 调用方 | 会话变量（@x） |
| INOUT | 双向 | 会话变量（@x），先赋好初值 |

**常见陷阱**：
- ❌ 在 MySQL 里给存储过程参数写默认值，调用时省略参数
- ✅ MySQL 不支持参数默认值，参数个数必须和定义一致，否则报错；可以传 NULL，再在过程里用 IFNULL 处理
- ❌ 不写 DELIMITER，直接在命令行里粘贴 CREATE PROCEDURE
- ✅ 第一个分号就会让客户端把不完整的语句发出去，报语法错误

**追问**：
- Q: OUT 参数和直接在过程里 SELECT 返回结果集有什么区别？
- A: OUT 参数适合返回少量单个值（比如一个总数），调用方可以把它当变量继续计算；SELECT 返回的是结果集，适合返回多行数据

**判断题**：
- ✅ OUT 参数可以把存储过程里算出的值传回调用方，比如 CALL GetOrderCountByStatus('Shipped', @total) 之后执行 SELECT @total —— 课件例子，结果是 303
- ❌ MySQL 存储过程的参数可以像 SQL Server 一样设置默认值，调用时省略 —— MySQL 不支持参数默认值，每个参数调用时都必须传

### 触发器（Trigger）

**概念**：触发器是和一张表关联的命名数据库对象，当表上发生指定的事件（INSERT、UPDATE、DELETE）时自动执行；由事件（Event）、时机（Timing：BEFORE 或 AFTER）和触发动作（Triggered Action）三部分组成

**一句话**：触发器不需要调用，表上发生 INSERT / UPDATE / DELETE 时自动执行；MySQL 的触发器是行级的（FOR EACH ROW），改了几行就触发几次；用 NEW 访问新值、OLD 访问旧值，BEFORE 触发器可以修改 NEW；常用于补充约束之外的规则、自动格式化数据、写审计日志，缺点是逻辑隐藏、难调试、影响写性能。

**详细解释**：
A trigger is a named database object that's associated with a table and activates when a particular event (INSERT, UPDATE, DELETE) occurs for the table。
Components：Event：The type of action (INSERT, UPDATE, DELETE) that will activate the trigger；Timing：Specifies when the trigger will be executed: BEFORE or AFTER the event；Triggered Action：The set of statements to execute when the trigger activates。
Triggers are often used to：Ensure data integrity rules beyond the standard constraints；Automatically format or transform data。
MySQL 例子：
```sql
DELIMITER //
CREATE TRIGGER trg_orders_before_insert
BEFORE INSERT ON orders
FOR EACH ROW
BEGIN
    SET NEW.status = UPPER(NEW.status);
END //
DELIMITER ;
```
NEW 和 OLD：INSERT 只有 NEW，DELETE 只有 OLD，UPDATE 两者都有；BEFORE 触发器可以 SET NEW.列 改写将要写入的值，AFTER 触发器只能读。
在 BEFORE 触发器里用 SIGNAL SQLSTATE '45000' 可以拒绝这次操作，实现 CHECK 做不到的复杂校验。
MySQL 触发器不能对同一张表再做 INSERT / UPDATE / DELETE（会报错），也不能返回结果集。

**问题**：什么是触发器？由哪几部分组成？常用来做什么？

**答案要点**：
1. 触发器绑定在一张表上，表上发生 INSERT、UPDATE、DELETE 时自动执行
2. 三个组成部分：Event（哪种操作）、Timing（BEFORE / AFTER）、Triggered Action（执行的语句）
3. MySQL 触发器是行级的（FOR EACH ROW），用 NEW、OLD 访问新旧值
4. 用途：标准约束之外的完整性规则、自动格式化或转换数据、审计日志
5. 缺点：逻辑隐藏、难调试，大量使用会拖慢写操作

**对比**：
| | 存储过程 | 触发器 |
|---|---|---|
| 执行方式 | 主动 CALL | 表上的事件发生时自动执行 |
| 参数 | IN、OUT、INOUT | 没有参数，用 NEW、OLD |
| 返回结果集 | 可以 | 不可以 |
| 绑定对象 | 不绑定表 | 绑定一张表的一种事件 |

**常见陷阱**：
- ❌ 以为一条 UPDATE 改了 100 行，触发器只执行一次
- ✅ MySQL 只支持行级触发器，每一行都会触发一次
- ❌ 在 AFTER UPDATE 触发器里 SET NEW.col = ... 想修改要写入的值
- ✅ 只有 BEFORE 触发器能修改 NEW，AFTER 时数据已经写入

**追问**：
- Q: 用触发器做审计日志要注意什么？
- A: 用 AFTER INSERT / UPDATE / DELETE 把 OLD、NEW 和操作时间写进日志表；触发器和原操作在同一个事务里，原操作回滚时日志也会回滚，并且每次写都会多一次插入，要考虑性能

**判断题**：
- ✅ 触发器由 INSERT、UPDATE、DELETE 事件自动激活，可以指定在事件之前（BEFORE）或之后（AFTER）执行 —— 课件：Event 和 Timing 两个组成部分
- ❌ 触发器需要像存储过程一样用 CALL 手动调用 —— 触发器在表上发生对应事件时自动执行，不能被 CALL
