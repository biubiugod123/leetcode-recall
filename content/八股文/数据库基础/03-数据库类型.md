# 数据库类型

### SQL 与 NoSQL

**概念**：关系型数据库（SQL）把结构化数据存在有行有列的表里，有严格的 schema，遵循 ACID；非关系型数据库（NoSQL）可以用 JSON、键值对、图等多种格式存数据，schema 灵活，遵循 BASE，容易水平扩展

**一句话**：SQL 数据库（MySQL、SQL Server、Oracle、PostgreSQL）适合结构固定、关系复杂、需要强一致事务的业务；NoSQL（MongoDB 文档型、Redis 键值型、Cassandra 列族型、Neo4j 图数据库）适合数据结构多变、数据量和并发很大、可以接受最终一致的场景；SQL 难水平扩展，NoSQL 容易水平扩展。

**详细解释**：
Relational Database (SQL)：Traditional way to store data (structured data)；Data is stored in tables with rows and columns；Rigid schema with well-defined relationships；Follows ACID；Difficult to scale horizontally；Examples: MySQL, MS SQL Server, Oracle DB, PostgreSQL。
Non-relational Database (NoSQL)：Developed more recently；Data can be stored in a variety of formats (JSON, k-v pairs, graphs)；Flexible schema with loose relationships (store unstructured data)；Follows BASE；Easy to scale horizontally；Examples: MongoDB, Couchbase, Neo4j。
ACID：Atomicity（原子性，要么全做要么全不做）、Consistency（一致性）、Isolation（隔离性）、Durability（持久性）。
BASE：Basically Available（基本可用）、Soft state（软状态）、Eventually consistent（最终一致）。
常见 DBMS：Oracle（PL/SQL）、Microsoft SQL Server（T-SQL）、MySQL；NoSQL：Redis、Cassandra、MongoDB、CouchDB、Neo4j、riak 等（课件把 PL/SQL 写成了 P/L SQL）。
水平扩展：加机器、把数据分片到多台服务器；垂直扩展：给一台机器加 CPU、内存。

**问题**：SQL 和 NoSQL 数据库有什么区别？分别适合什么场景？

**答案要点**：
1. SQL：表结构、严格 schema、关系清晰；NoSQL：JSON / 键值 / 列族 / 图，schema 灵活
2. SQL 遵循 ACID，强一致；NoSQL 多遵循 BASE，最终一致
3. SQL 难水平扩展（多靠垂直扩展），NoSQL 容易水平扩展
4. SQL 例子：MySQL、Oracle、SQL Server、PostgreSQL；NoSQL：MongoDB、Redis、Cassandra、Neo4j
5. 交易、账务用 SQL；缓存、日志、社交关系、海量数据常用 NoSQL

**对比**：
| | SQL | NoSQL |
|---|---|---|
| 数据格式 | 表（行、列） | JSON、键值对、列族、图 |
| Schema | 严格 | 灵活 |
| 事务 | ACID | BASE |
| 扩展 | 难以水平扩展 | 容易水平扩展 |
| 例子 | MySQL、PostgreSQL、Oracle | MongoDB、Redis、Neo4j |

**常见陷阱**：
- ❌ 认为 NoSQL 就是"不能用 SQL 查询"或"完全没有 schema"
- ✅ NoSQL 指非关系型（Not only SQL），schema 灵活而不是没有，有的也支持类 SQL 查询
- ❌ 认为 NoSQL 一定比 SQL 快、可以完全替代 SQL
- ✅ 各有适用场景，很多系统同时使用 MySQL 和 Redis

**追问**：
- Q: Redis 通常在系统里扮演什么角色？
- A: 内存中的键值数据库，常用作缓存（放热点数据，减轻 MySQL 压力），也用来做计数器、分布式锁、排行榜等

**判断题**：
- ✅ 关系型数据库遵循 ACID 原则 —— 原子性、一致性、隔离性、持久性
- ❌ 关系型数据库比 NoSQL 更容易水平扩展 —— 关系型数据库难以水平扩展，NoSQL 更容易

### ACID 与 BASE

**概念**：ACID 是关系型数据库事务的四个特性：原子性、一致性、隔离性、持久性；BASE 是很多 NoSQL 系统采用的思路：基本可用、软状态、最终一致

**一句话**：原子性是一个事务里的操作要么全部成功、要么全部回滚；一致性是事务前后数据都满足约束；隔离性是并发事务互不干扰；持久性是提交后的数据不会因为宕机丢失；BASE 放宽了一致性要求，允许短时间不一致，换取高可用和易扩展。

**详细解释**：
ACID（课件在 SQL vs NoSQL 里提到 SQL Follows ACID）：
Atomicity：转账时扣款和入账要么都成功，要么都不发生
Consistency：事务执行前后，数据都满足所有约束（比如余额不能为负、总金额不变）
Isolation：多个事务并发执行时，彼此看不到对方未提交的中间状态
Durability：事务提交后，即使数据库崩溃，数据也不会丢
BASE（NoSQL Follows BASE）：
Basically Available：出现故障时仍保证核心功能可用，可能降级
Soft state：允许系统存在中间状态，数据在副本间同步需要时间
Eventually consistent：经过一段时间后，所有副本最终会达到一致
相关理论：CAP 定理指出分布式系统不能同时完全满足一致性（C）、可用性（A）和分区容错（P），BASE 是偏向 AP 的选择。

**问题**：说一下 ACID 和 BASE

**答案要点**：
1. Atomicity：事务中的操作要么全做，要么全不做
2. Consistency：事务前后数据满足所有约束
3. Isolation：并发事务互不干扰
4. Durability：提交后的数据永久保存
5. BASE：基本可用、软状态、最终一致，以一致性换可用性和扩展性

**对比**：
| | ACID | BASE |
|---|---|---|
| 一致性 | 强一致 | 最终一致 |
| 侧重 | 正确性 | 可用性、扩展性 |
| 典型系统 | MySQL、PostgreSQL、Oracle | Cassandra、DynamoDB 等分布式 NoSQL |

**常见陷阱**：
- ❌ 把 ACID 的 Consistency 和分布式里"副本一致"混为一谈
- ✅ ACID 的 C 指数据满足约束和业务规则；CAP / BASE 里的一致性指多个副本的数据是否相同

**追问**：
- Q: 银行转账为什么一般用关系型数据库？
- A: 需要原子性和强一致：扣款和入账必须同时成功或同时失败，不能出现钱扣了没到账的中间状态

**判断题**：
- ✅ 原子性（Atomicity）保证事务中的操作要么全部完成，要么全部不做 —— 失败时会回滚到事务开始前的状态
- ❌ BASE 中的 E 表示 Exactly consistent（精确一致） —— E 是 Eventually consistent，最终一致
