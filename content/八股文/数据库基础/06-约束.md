# 约束

### 约束的种类

**概念**：约束（Constraint）是加在表上的规则，规定数据必须满足的属性；包括主键、唯一键、外键等键约束，以及 NOT NULL、CHECK、DEFAULT 和数据类型等其他约束

**一句话**：主键每表一个、唯一且不能为 NULL；唯一键可以有多个，保证值不重复但允许 NULL（MySQL 允许多个 NULL，SQL Server 只允许一个）；外键引用其他表的主键，被引用的记录必须先存在、删除时要先删引用它的记录；NOT NULL 禁止空值，CHECK 检查自定义规则，DEFAULT 在没给值时填默认值。

**详细解释**：
A constraint is usually associated with a table；They define certain properties that data in a database must comply with。
Key Constraints（课件以 SQL Server 为例）：
Primary Key (PK)：1 per table | Unique clustered index | not null
Unique Key：999 per table | Unique non-clustered index | 1 null allowed（"999 个、只允许 1 个 NULL"是 SQL Server 的规则，MySQL 的 UNIQUE 允许多个 NULL）
Foreign Key (FK)：cannot exist before PK | Must be deleted before PK
Other Constraints：Null & Not Null（是否允许空）；Check（数据必须满足规则）；Default（没给值时使用这个值）；Data Types：Char(2) → 州代码（NY、CA）；Varchar(10) → 字符串。
CHAR(n) 是定长，不足补空格，适合长度固定的值；VARCHAR(n) 是变长，按实际长度存储。
MySQL 8.0.16 起才真正执行 CHECK 约束，之前的版本会解析但忽略它。

**问题**：数据库有哪些约束？主键和唯一键有什么区别？

**答案要点**：
1. 主键：每表一个，唯一且非空，通常是聚集索引
2. 唯一键：可以有多个，保证不重复，允许 NULL
3. 外键：引用另一张表的主键，保证参照完整性
4. NOT NULL、CHECK、DEFAULT 约束列的取值
5. 数据类型本身也是约束：CHAR 定长、VARCHAR 变长

**对比**：
| | 主键 PRIMARY KEY | 唯一键 UNIQUE |
|---|---|---|
| 每表数量 | 1 个 | 多个 |
| 是否允许 NULL | 不允许 | 允许（MySQL 可以多个 NULL） |
| 默认索引 | 聚集索引（InnoDB、SQL Server） | 非聚集（二级）索引 |
| 作用 | 唯一标识一行 | 保证某列不重复（如邮箱） |

**常见陷阱**：
- ❌ 认为 UNIQUE 列只能有一个 NULL
- ✅ 这取决于数据库：MySQL、PostgreSQL 允许多个 NULL，SQL Server 只允许一个
- ❌ 认为一张表可以有多个主键
- ✅ 只能有一个主键，但主键可以由多列组成（复合主键）

**追问**：
- Q: 为什么给邮箱列加 UNIQUE 而不是把它设为主键？
- A: 邮箱可能会修改，用作主键时所有引用它的外键都要跟着改；用自增 ID 当主键，邮箱加唯一约束更稳定

**代码题**：下面 SQL 执行后，最后一条查询的结果是什么？（每行用 | 隔开）

```sql
CREATE TABLE orders (id INT PRIMARY KEY, status VARCHAR(10) DEFAULT 'NEW');
INSERT INTO orders (id) VALUES (1);
INSERT INTO orders VALUES (2, 'PAID');
SELECT id, status FROM orders ORDER BY id;
```

- [x] 1 NEW | 2 PAID
- [ ] 1 NULL | 2 PAID
- [ ] 执行报错
- [ ] 2 PAID

解析：第一条 INSERT 没有给 status 赋值，使用 DEFAULT 'NEW'；第二条显式给了 'PAID'。

**代码题**：下面 SQL 执行后，最后一条查询的结果是什么？

```sql
CREATE TABLE accounts (email VARCHAR(30) UNIQUE);
INSERT INTO accounts VALUES (NULL), (NULL), ('a@x.com');
SELECT COUNT(*) FROM accounts;
```

- [x] 3
- [ ] 2
- [ ] 1
- [ ] 执行报错

解析：UNIQUE 约束不把 NULL 当成重复值，MySQL（以及这里使用的 SQLite）允许多个 NULL，三行都能插入；在 SQL Server 中第二个 NULL 会报错。

**代码题**：下面 SQL 执行结果是什么？

```sql
CREATE TABLE bank (id INT PRIMARY KEY, balance INT NOT NULL CHECK (balance >= 0));
INSERT INTO bank VALUES (1, 100);
INSERT INTO bank VALUES (2, -5);
SELECT COUNT(*) FROM bank;
```

- [ ] 2
- [ ] 1
- [x] 执行报错
- [ ] 查询结果为空

解析：第二条 INSERT 的余额是 -5，违反了 CHECK (balance >= 0) 约束，执行报错。

**判断题**：
- ✅ 一张表只能有一个主键，但主键可以由多列组成 —— 多列组成的叫复合主键
- ❌ 加了 UNIQUE 约束的列不能出现 NULL —— UNIQUE 允许 NULL，禁止空值要用 NOT NULL

### 添加约束的方式

**概念**：约束可以在建表时直接写在列定义后面（列级约束），可以写在 CREATE TABLE 的最后（表级约束），也可以先建表再用 ALTER TABLE 添加

**一句话**：列级写法最简洁，比如 `employee_id INT PRIMARY KEY`、`name CHAR(50) NOT NULL`；表级写法适合涉及多列的约束，比如 `PRIMARY KEY (a, b)`、`UNIQUE (first_name, last_name)`、`FOREIGN KEY (ProductID) REFERENCES Products(ProductID)`；已有的表用 `ALTER TABLE ... ADD PRIMARY KEY / ADD UNIQUE` 补加约束。

**详细解释**：
Adding constraints to a table：Constraints are used to specify rules for the data in table；Type：NOT NULL, UNIQUE, PRIMARY KEY。
三种方式：
1. Create table then alter to add constraints：
```sql
CREATE TABLE Students (StudentID INT, FirstName VARCHAR(255), LastName VARCHAR(255));
ALTER TABLE Students ADD PRIMARY KEY (StudentID);
ALTER TABLE Students ADD UNIQUE (FirstName, LastName);
```
2. Add constraint as we specify the column in table（列级）：
```sql
CREATE TABLE employee (
    employee_id INT AUTO_INCREMENT PRIMARY KEY,
    first_name CHAR(50) NOT NULL,
    last_name CHAR(70) NOT NULL
);
```
3. Add constraints in the same create statement（表级）：
```sql
CREATE TABLE Orders (
    OrderID INT,
    ProductID INT,
    PRIMARY KEY (OrderID),
    FOREIGN KEY (ProductID) REFERENCES Products(ProductID)
);
```
NOT NULL 只能写成列级约束；复合主键、复合唯一键只能写成表级约束。表级约束可以用 CONSTRAINT 名字 起名，方便以后删除。

**问题**：给表添加约束有哪几种方式？

**答案要点**：
1. 列级：在列定义后面直接写 PRIMARY KEY、NOT NULL、UNIQUE 等
2. 表级：在 CREATE TABLE 的最后写，适合多列约束和外键
3. 建表后用 ALTER TABLE ... ADD 补加约束
4. NOT NULL 只能列级；复合主键、复合唯一只能表级
5. 给约束起名（CONSTRAINT xxx）便于以后修改或删除

**常见陷阱**：
- ❌ 想让"名 + 姓"组合唯一，分别给两列加 UNIQUE
- ✅ 那样两列各自不能重复，应该用表级的 UNIQUE (first_name, last_name)

**追问**：
- Q: 已经有重复数据的表，还能加 UNIQUE 约束吗？
- A: 不能，ALTER TABLE ADD UNIQUE 会因为已有重复值而失败，要先清理重复数据

**代码题**：下面 SQL 执行结果是什么？

```sql
CREATE TABLE students (id INT PRIMARY KEY, first_name VARCHAR(20), last_name VARCHAR(20), UNIQUE (first_name, last_name));
INSERT INTO students VALUES (1, 'Tom', 'Lee'), (2, 'Tom', 'Wu');
INSERT INTO students VALUES (3, 'Tom', 'Lee');
SELECT COUNT(*) FROM students;
```

- [ ] 3
- [ ] 2
- [x] 执行报错
- [ ] 1

解析：表级约束 UNIQUE (first_name, last_name) 要求"名 + 姓"的组合不重复；前两行组合不同可以插入，第三行和第一行都是 Tom Lee，执行报错。

**代码题**：下面 SQL 执行结果是什么？

```sql
CREATE TABLE employee (id INT PRIMARY KEY, first_name CHAR(50) NOT NULL, last_name CHAR(70) NOT NULL);
INSERT INTO employee (id, first_name) VALUES (1, 'Ann');
SELECT COUNT(*) FROM employee;
```

- [ ] 1
- [ ] 0
- [x] 执行报错
- [ ] 查询结果为空

解析：last_name 有 NOT NULL 约束且没有默认值，INSERT 没给它赋值，相当于插入 NULL，执行报错。

**判断题**：
- ✅ 复合唯一约束需要用表级写法，比如 UNIQUE (first_name, last_name) —— 列级约束只能作用于单个列
- ❌ 约束只能在 CREATE TABLE 时定义，建表后不能再添加 —— 可以用 ALTER TABLE 补加约束
